## 分かったこと

### 1. 「数値まで取れるか」は、相手が数字を見出しに出しているかで決まる

1回目は「企業や省庁からは数値が取れない」と結論しかけたが、**それは早すぎた**。
`allowed_domains` の向け先を変えたら、数値まで一気に取れた。

| 数値まで取れる | 所在しか取れない |
|---|---|
| 計測機関（Artificial Analysis の Index・単価・トークン毎秒） | 審議会PDFの本文に埋まった数値（電力の待ち年数） |
| arXiv の abstract（1,547本・15日間・5世界） | 法令の正文（条番号・施行日） |
| 製品ブログの価格表（$0.75/$3.75、切替日、64k） | 企業プレスリリースの**発表日** |
| **調査機関のプレスリリース**（JIPDEC 36%、Gallup 52%/27%/18%/79%） | |
| **集計元**（Crunchbase $510B、上位2社で43%） | |
| **省庁の推計の要旨**（340万人不足／440万人余剰） | |

**要点：報道されることを前提に数字を要約している相手からは取れる。**
会議資料のPDFと法令の正文だけが、本当に開かないと読めない。

### 2. 検証層（L4）が2件を撃墜した

- **Snowflake $200M** … 「今週の話題」として拾ったが、再検索で**2025年12月3日**発表と判明。
  検索スニペットは日付を落とす。**日付だけはドメイン制限を外して引き直す**工程を必須にする
- **資金調達の総額** … 二次情報の中で「AIスタートアップがH1で$407B」と
  「通年$120B超の見込み」が**同時に出回っていた**（桁が合わない）。
  集計元のCrunchbaseに当たって $510B（全分野・H1）／上位2社で43% に落ち着いた

**L3の深掘りだけで書いていたら、2件とも間違った形で載っていた。**

### 3. 網羅性は「領域を先に切る」ことでしか担保できない

1回目と2回目でやったことは同じで、違いは `watchlist.yml` があるかどうかだけ。
**面白い話題を拾っていくと、必ず技術に寄る。** 法規制・人材・社会は「今週の目玉」になりにくいのに、
おざけんの読者にとってはそちらのほうが効く。**先に枠を決めて、埋めに行く**のが正しい。

### 4. 既存資料との突き合わせは動いた。結果は「食い違いゼロ、裏付けもゼロ」

`find.py` で92本を検索できた（システムの `cryptography` が壊れていたので入れ直しが必要だった）。
今週の数字と**食い違う記述は1つも無かった**。ただし
**「経産省の就業構造推計」「Gallup」「JIPDEC」を引いている資料も1つも無かった。**

つまり人材・組織・社会の資料が、いま公的な数字の裏付けなしで語られている。
主張を変える必要はないが、根拠を1行足せる箇所が並んだ。
→ `crosscheck-suggestions.md`（**提案のみ。何も直していない**）

### 5. 道具の不具合を1つ見つけた

`find.py` の `--in` は、続く引数が検索語としても拾われる。
`find.py --heads --in 02_models` は「02_models という語」を探しに行って0件になる。
`args` から `--in` の次の要素を除けば直る。**今回は触っていない。**
