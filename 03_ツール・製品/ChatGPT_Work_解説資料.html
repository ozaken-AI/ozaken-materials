ChatGPT Work / 2026.07.09

ChatGPT Workは、
ChatGPTの主語を
「答える」から「仕上げる」に変えた

OpenAIが2026年7月9日（米国時間）に発表した新機能「ChatGPT Work」。 実務で何に効くのか、そして Claude Cowork・Copilot・Gemini といった 他のエージェント系ツールと何が決定的に違うのかを整理する。

Section 01 — Chat / Work / Codex

最初に覚えるのは機能名ではなく、
3つのタブの「役割分担」だ

ChatGPT Workは、GPT-5.6を搭載し、接続したアプリ・ファイル・ブラウザを横断して情報を集め、 計画を立て、アクションを実行し、シート／スライド／ドキュメント／Webアプリまで作り切るエージェント機能。 複雑なプロジェクトを小さなステップに分解し、必要に応じて数時間にわたって作業を続ける。 その結果、ChatGPTは Chat・Work・Codex の3タブ構成になった。 混乱の大半は、この3つを「同じChatGPTの違うモード」だと思うところから始まる。別の生き物として覚えたほうが早い。

Chat — 話す相手

従来のChatGPT。考えを整理したいとき、壁打ちしたいときはここで十分。

任せるもの
質問・相談・アイデア出し
受け取るもの
言葉（答え）
消費
軽い
使える場所
Web・スマホ・デスクトップ

Work — 仕上げる相手

今回の主役。ゴールを渡すと、情報を集めて成果物の形まで持っていく。

任せるもの
調査・分析・資料づくり
受け取るもの
スライド、シート、ドキュメントなどの成果物
消費
重い（Codexなどとプール共有）
使える場所
Web・スマホ（有料プランのみ）／デスクトップ（無料プラン含む全プラン）

Codex — 動かす相手

元は開発者向け。返ってくるのは文章ではなく、変わったPCそのもの。

任せるもの
自分のPC内のファイル操作・作業代行
受け取るもの
変化したPCの状態（片付いたフォルダ、動くツール）
消費
重い（Workなどとプール共有）
使える場所
デスクトップのみ（Web・スマホでは選べない）

3タブを分ける軸は「何が返ってくるか」

Chatは言葉が返る。Workは成果物（ファイル）が返る。Codexは自分のPCの状態そのものが変わって返る。 任せる前に「今日ほしいのはこの3つのどれか」を決めるだけで、タブ選びはほぼ間違えなくなる。

正体は「Codexの一般業務化」

開発者向けコーディングエージェントCodexの設計思想を、そのままナレッジワークへ展開したものがWork。 週500万人超のCodex利用者のうち、100万人以上がすでに開発以外の業務で使っていた事実が土台にある。

提供状況（2026年7月9日発表時点）：Web／モバイルのWorkはPro・Enterprise・Eduから順次、PlusとBusinessへは数日で拡大。 デスクトップアプリ（Mac／Windows）ではChat・Work・CodexがFreeを含む全プランで利用可能。 なお、CodexアプリがそのままChatGPTデスクトップアプリになり、従来のデスクトップアプリは「ChatGPT Classic」へ改称され、今後の更新は提供されない。

Section 02 — Anatomy

ChatGPT Workを構成する5つの部品

「エージェントがすごい」で終わらせず、何が動いているのかを分解する。 実務設計はこの5点の組み合わせでしか考えられない。

1

プラグイン — コンテキストの入口

Slack、Microsoft Teams、Google Drive、SharePoint、メール、カレンダー、CRM、プロジェクトトラッカー等に接続。プロンプト内容から参照先を自動判断するほか、「@アプリ名」で明示指定もできる。統合プラグインディレクトリに集約され、会話中に関連プラグインが提案される。

2

Scheduled Tasks — 時間とイベントのトリガー

1回だけの実行、定期実行、イベント発生時の実行、変化の監視に対応。「毎週のSlack更新を確認して定例会議のアジェンダを更新」「毎朝ダッシュボードを確認して差分をレポート送信」「新しい顧客フィードバックが届いたらプレゼンを更新」といった“追い続けないと終わらない仕事”を渡せる。

3

Sites（パブリックベータ）— 成果物の出口

作業内容をインタラクティブなサイト／Webアプリに変換し、URLでチーム内や一般に共有できる。ライブダッシュボード、プロジェクトトラッカー、ローンチカレンダー、プロトタイプ、社内ポータル、インタラクティブレポートが想定用途。元データが変われば更新もできる。

4

内蔵ブラウザ＋Computer Use — 手足

デスクトップ版に内蔵ブラウザが追加され、市場調査・情報源比較・Google WorkspaceやMicrosoft 365ファイルの編集をアプリ内で完結。Computer Useではクリック・入力・ファイル移動をバックグラウンドで代行する。Chrome拡張も更新され、単体ブラウザAtlasは段階的に提供終了へ。

5

GPT-5.6 — 動力源

同日一般提供が始まった最新フロンティアモデル。複数ステップのタスクの推論と、テンプレートや参照ファイルに沿った資料作成で最先端の性能を出すとされる。ChatGPT Workの「数時間走り続ける」設計はこのモデルが前提にある。

OK
Ozaken's One Point
小澤健祐（おざけん）

正直に言うと、5つの部品のうち4つは既にどこかにあったものだ。定期実行もPC操作もプラグインも初出ではない。 それでもこれを重く見るべきなのは、OpenAIが旧アプリを「Classic」と呼び、Codexを本体に据え直したからだ。 つまり今回の発表の中身は機能ではなく宣言である。年間300回以上の企業研修で見てきた限り、 製品側が名前で示した方向転換は、半年遅れで必ず現場の要求水準になる。

Section 03 — Use Cases

効くのは「作業」ではなく、部門をまたいで散らかっている仕事だ

単発の資料作成なら従来のChatGPTで足りる。ChatGPT Workが効くのは、 複数ツールに情報が分散していて、誰も全体を見られていない領域。公式に紹介された事例から実務の型を抽出する。

営業：リードの取りこぼし検出

Zapierの事例では、CRM・メール等を横断して顧客接点をたどり、フォローアップが途切れた箇所を特定。週次の経営層向けダッシュボードを自動生成し、7桁規模（数百万ドル）の潜在売上を可視化した。

PMO：ローンチ確認の型化

RingCentralの事例では、リリース計画・Jiraタスク・GTMスケジュールを突き合わせ、抜けている手順・阻害要因・不明確な担当範囲を検出。担当者と次アクションを明記したソース付きレポートを生成し、PM1人分の支援が約50人分に拡大した。

戦略：競合ベンチマーク

Virgin Atlanticの事例では、評価対象のカスタマージャーニーと競合航空会社のリストを渡し、各社の提供内容を調査・評価してチームが検証できるデータセット化。数週間かかっていた分析が数時間になった。

イベント：準備と事後分析

NVIDIAの事例では、カンファレンス準備のExcelワークフロー（事前工数の約40%）を置換。登録済みアカウント・予定ミーティング・現場の準備状況を追跡し、終了後は数百件のセッション文字起こしと商談メモを統合して達成度を評価した。

財務：月次決算と予測

OpenAI社内では、元データの特定 → Excel／Sheetsへの取り込み → 照合 → スライド作成 → 結果検証までを支援し、月末締めと予測が数日から数時間に。空いた時間は経営層への助言に振り向けられている。

営業技術：PoCの高速化

OpenAI社内の営業では、通常数週間かかるディスカバリー面談から、課題に合わせた概念実証を24時間以内に作成。メモを構造化し、依頼をソリューションアーキテクトにつなぎ、技術チームと連携させた。

共通しているのは「複数ツールに散った情報を突き合わせて、定期的に、成果物の形で吐き出す」という構造。 逆に言えば、情報が1つのファイルに閉じている業務にChatGPT Workを使う旨みは薄い。

Section 04 — Comparison

違いはモデル性能ではない。「仕事がどこから始まるか」だ

2026年前半、主要ベンダーのエージェント製品は機能面で急速に同質化した。 定期実行もPC操作もコネクタもほぼ全社が持っている。差が残るのは起点・権限モデル・課金の3点である。

ChatGPT Work

起点は「接続したクラウド」

プラグインで社内SaaSに接続し、そこから文脈を集めるのが基本形。デスクトップではローカルファイル・内蔵ブラウザ・Computer Useも使える。Sitesという“共有可能なWebアプリ”を出口に持つのは現時点でここだけの特徴。

vs
Claude Cowork

起点は「許可したローカルフォルダ」

2026年1月にリサーチプレビュー、4月9日にGA。ユーザーが明示的に許可したフォルダの中でファイルを読み書きする設計が中核で、許可外のフォルダはClaudeから見えない。手元のファイル群を整理・統合・成果物化する仕事に強い。

この非対称が意味すること

ChatGPT Workは「社内システムに接続してから仕事が始まる」ため、価値が出るまでに管理者の承認とコネクタ整備が要る。 一方Claude Coworkは「フォルダを1つ許可すれば今日から動く」ため、個人が先に始めて情シスが後から追いかける構図になりやすい。 導入の速さと統制のしやすさが、そのままトレードオフになっている。どちらが優れているかではなく、 組織が「先に配るのか、先に整えるのか」という方針の違いが選定を決める。

Microsoft 365 Copilot / Copilot Cowork

起点はM365テナント。Word・Excel・Outlook・Teamsの中で強く、Purviewや管理者統制などガバナンス基盤が最も厚い。2026年3月に発表されたCopilot CoworkはAnthropicのエージェントエンジンを採用しつつMicrosoftの基盤で包んだ別製品で、6月にGA。名前は似ているがClaude Coworkとは適用領域が異なる。

Gemini for Workspace

起点はGoogle Workspace。Gmail・Docs・Sheets・Driveの中に溶け込む「スイート内アシスタント」の性格が強く、多くのプランに標準同梱で追加ライセンス費がかからない。長文読解・マルチモーダルに強いが、自律的にPCやSaaSを横断して仕事を完遂する方向性は他社より控えめ。

Claude Code / Codex

いずれも開発者向けのCLI／コーディングエージェント。今回のChatGPT WorkもClaude Coworkも、この2つの技術を非エンジニアに開いたものという点で出自は同じ。エージェント製品の系譜は「開発現場で先に実証され、知的業務に降りてくる」という一本の流れで理解できる。

Ozaken's One Point

「どのエージェントが一番賢いか」を比べる会議は、ほぼ確実に時間の無駄になる。決めるべき問いは一つだけで、 自社の情報が今どこに溜まっているかだ。M365ならCopilot、WorkspaceならGemini、 手元のファイルが主戦場ならCowork、SaaSが散らかっているならChatGPT Work——選定はここでほぼ決まる。 比較表を作る前に、社内のデータの住所を先に書き出したほうが早い。

Section 05 — Before You Deploy

導入前に潰しておくべき、3つの現実的な論点

エージェントは「配れば使われる」ものではない。特に課金構造とガバナンスは、 チャット時代の感覚のままだと必ず事故る。

① 「月額いくらで使い放題」ではない

Chatの感覚のままWorkを使うと枠が溶ける。ChatGPT Workは通常のチャットリクエストより長く複雑な作業向けに設計されているため使用量の扱いが異なり、Codexと同じ仕組みに従う。しかもWorkとCodexは同じプール（プランに含まれる使用量の枠）を分け合うので、片方を回せばもう片方の枠も減る。重い調査を1本流しただけで一日分を使い切ることもある、という前提で運用を組む。

② 誰に、どこまで、いくらまで

何にアクセスさせるか、いつ確認を求めさせるか、アクション前に承認を要求するかはユーザー側が決める設計。Enterprise／Eduの管理者はプラグイン接続、ブラウザ利用とネットワークアクセス、接続システム内の機密性の高いアクションを一元管理でき、Compliance APIで会話とアクションを可視化できる。使用量についても、Admin Consoleでワークスペース既定値・グループ上限・個別例外を設定し、全体の上限を上げずに必要な人だけ枠を広げられる。

③ 参照先データの整備度が精度を決める

これはCopilotでもGeminiでも共通する現場の鉄則だが、エージェントの出力品質は「参照できる社内データの整理度」に直結する。フォルダ名・ファイル名に統一ルールがない組織では、AIが誤ったファイルを引用し、「AIは信用できない」という結論だけが残る。導入前の棚卸しが最大の投資対効果を生む。

④ 成果物をそのまま最終版にしない

自動レビュー機構は用意されており、敵対的レッドチーミングでは保護対象データの抽出試行を100%ブロックしたと報告されている。それでも実務上は、エージェントの判断（例：「要返信」の選別）が人間の判断とずれる事例が各社で報告されている。人が最終確認する工程を残す前提で業務設計すること。

Summary

ChatGPT Workで問われるのは
「AIを使いこなせるか」ではない。
自社の仕事が、渡せる形に
分解されているかどうかだ。
