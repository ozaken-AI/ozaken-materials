# ハマりどころ

実際に踏んだものだけを載せている。読んでおくと、同じ穴に落ちずに済む。

## 図版

### `<b>` や `<br>` がそのまま文字として出る
SVGの中では使えない。`lines()` も `esc()` も、タグを実体参照に変える。
**強調したいときは色を変えるか、行を分ける。**
HTML本文（カードの中）では `<b>` を使ってよい。

### 英単語が途中で切れる
`wrap()` は英数字の連なりを途中で切らないようにしてあるが、
極端に幅が狭いと戻しきれない。`BluStellar` が `BluSt` / `ellar` になったことがある。
**列を広げるか、文字数上限を守る。**

### 同じページに同じ図版を2つ置くと矢印が消える
`fig_gap` `fig_issues` `fig_flow` `fig_cycle` `fig_tree` は SVG の `marker` を使う。
id が衝突すると、後から描いたほうの矢印が壊れる。
**`uid` に必ず違う文字列を渡す。** `check()` が重複を弾く。

### 回転させたテキストに矢印記号を入れると弾かれる
`fig_quad` `fig_map` の y軸ラベル。`↑` を入れると向きが破綻するので、
`check()` が落とす。「効果の大きさ ↑」ではなく「効果の大きさ」と書く。

### 文字が箱からはみ出す
いちばん多い。**SVGは折り返さない。** `references/figures.md` の文字数上限を守る。
そのうえで**必ずレンダリングして目で見る**。コードは通るし、ブラウザもエラーを出さない。

### 図版を差し替えたら、後ろのカードが消えた
`<div class="figure">[\s\S]*?</div>\s*</div>` のような正規表現で図版を取ろうとすると、
中の `<div class="figure-scroll">` を数え損ねて、**後ろのカードまで巻き込んで消す**。
実際に2本の資料でカードが消えた。差し替えには `page_parts.replace_figure()` を使う。
開きタグと閉じタグを数えて、対応する `</div>` を見つける。

### 並列のものを、矢印でつないでしまう
`fig_flow` は順序のある工程のための図。優劣も順序もない4つを並べるのに使うと、
**左から右へ進むもの・右のほうが上位** という誤解を与える。
並列なら `fig_cols`。実際にエージェント化の4方向でこれをやり、指摘を受けた。

### 汎用の図に、意味の合わないラベルが残る
`fig_issues` は「壁 1」「壁 2」、`fig_gap` は「いま」「3年後の到達像」を
既定で持っている。手順を描くのに `fig_issues` を使うと「壁1: 棚卸し」になる。
**形が似ているからと流用しない。** `fig_flow` を使うか、新しい関数を足す。

### 動きの印を振り直したら、SVGが壊れた
`_animate()` は要素に `class` と `style` を足す。すでに `class="..."` を持つ要素に
素朴に足すと **`class` が2つある要素**ができ、ブラウザは後ろを無視するので図が消える。
自己閉じタグの `/` を属性ごと巻き込むと `<rect ... / class="a-fade">` になる。
どちらも実際に本番の図を3つ壊した。**印を振る処理を触ったら、必ず全SVGの妥当性を確かめる。**

### 自前でないキーフレーム名を借りると、要素が丸ごと消える
`a-flow` の登場アニメーションに `figFade` を使ったところ、その名前を定義していない
17本の資料で `opacity:0` のまま止まり、**矢印が全部消えた**。
新しい演出を足すときは、**キーフレームも同じ場所で定義する**（`ozFxIn` など `oz` で始める）。
古い資料は、いま入っているCSSが自分と同じとは限らない。

### 常時動く印が付きすぎる
`a-flow` は矢印と破線、`a-breathe` は細い色帯と小さな塗り円にしか付けない。
判定を緩めると画面中がちらついて、話の邪魔になる。
**動かすかどうかは「意味のある線か」で決める。**

## 暗号化

### `lockbox.encrypt` の引数順
`encrypt(path, pw, plaintext)`。`(path, plaintext, pw)` と書いて
「パスワードが違います」で悩んだことがある。

### `create` と `encrypt` の使い分け
- `encrypt(path, pw, html)` … **本文だけ差し替える。鍵はすべて維持される**
- `create(tpl, html, out, [pw...])` … **鍵を作り直す。既存のパスワードは無効になる**

既存資料の中身を直すときに `create` を使うと、配布済みのパスワードが死ぬ。
**直すだけなら必ず `encrypt`。**

### 暗号化ページに演出を当て直すとき
`apply_*.py` は「印がすでにあれば何もしない」ので、CSSを直しても反映されない。
`reapply.py <対象>` を使う。古い版を剥がしてから入れ直す。

### 共有カードの画像をPNGで刷ると、リポジトリが膨らむ
表紙と同じグラデーションは、PNGだと1枚500KBになる。78枚で37MB。
**JPEG（品質88）で刷る。** 7MBに収まり、SNSの表示では見分けがつかない。

### 共有カードの日本語が資料と別物の書体になる
この環境に入っている日本語書体はIPAゴシックだけ。
`make_ogp.mjs` は書体を都度取ってきて `file://` で読ませる。
`setContent` で流し込むと `about:blank` 扱いになり **`file://` の書体を拒まれる**ので、
HTMLをいったん書体と同じ場所に書き出してから `goto` する。

### 作り直したら、カード見出しのチップが素の文字になった
`.lede` `.mth` `.num` のCSSは `page_parts.EXTRA_CSS` にあり、`publish.py` が足している。
`build_page.build` だけで組み直すと、**資料まるごとから体裁が落ちる**。
作り直しは `publish.py … --update` を通す。鍵は維持される。

### 図版が真っ白に写る
`.figure` は画面に入って初めて `anim-on` が付く。背の高い面を1枚に撮ると、
撮影中に付いても登場アニメーションが間に合わず、**図が丸ごと白く写る**。
`shot_secs.mjs` は撮る前に `anim-on` を付けている。自前で撮るときも同じことをする。

### 円環の左右のラベルが頭から切れる
`fig_loop4` の左右の辺には横幅がほとんど無い。4文字を超えると画面の外へ出て、
「一周して、前より深く」が「り深く」になった。いまは90度倒して置いている。

## 扉

### リード文が5行になって、扉が文字の壁になる
1本ではなく**11本**まとめて起きた。どれも同じ形で、
「AとBとCとDを扱います」とリード文で列挙していた。
リード文の上限は**表示幅210**（3〜4行）。全103本を実際に描画して測ると、
4行に収まっているものの最大が196、5行になるものの最小が252だったので、
あいだを取ってこの値にしてある。
**並べたい項目はリード文ではなく目次（`hero(..., toc=[...])`）へ。**

### 題が3行になって、署名が画面から消える
根が深かった。`.hero` は `display:flex` で、子は既定で中身なりの幅に縮む。
そのため `.inner{max-width:1160px}` が効かず、いちばん広い子である
`.hero-copy{max-width:620px}` が題の幅を決めていた。
**題に使える幅が620px＝全角12字ほどしか無かった**ということで、
しかも資料ごとに520〜986pxとばらついていた。
`normalize_hero.py` の `.hero > .inner` に `width:100%` を1行足して解決。
これだけで11本中4本が直っている。

### 検査が、特定の資料だけ素通りしていた
`check_hero` が `<h1 class="hero-title">` を**完全一致**で探していた。
演出が当たった資料は `class="hero-title rise d2"` になっているので、
そこだけ検査そのものが走らず、長い題が公開まで通っていた。
**class で要素を拾う検査は、必ず `[^"]*\bhero-title\b[^"]*` の形で書く。**
同じ理由で `hero-copy rise d4` も1本すり抜けていた。

### 検査を足したのに、数に出ていなかった
`lint_all.py` は `check()` を呼んでいたが、資料を「要修正」に入れる判定には
`check_tokens`（色と書体）しか使っていなかった。
そのため構成の指摘も図の文字の混入も拾われず、
**「104本すべて規定どおり」と出ていた。**
実際には便覧そのものに7か所のマークダウンが残っていた。
**検査を足したら、それが数に出るところまで確かめる。**

### 図の題とキャプションにマークダウンを書く
`_fig()` が `esc()` を通すので、`**強調**` は太字にならず
`**` の2文字がそのまま画面に出る。SVGの外なので、
SVG本文だけを見ていた検査では拾えなかった。
`&lt;table&gt;` と書くと、画面には `&lt;table&gt;` と出る（二重の実体参照）。
どちらも `check()` が弾くようにしてある。

### カードの見出しが、語の途中で折れる
`text-wrap: balance` を当てていたのが原因。
balance は**行の長さを揃えることを優先して、`word-break: auto-phrase` の
文節区切りを無視する**。カードは幅が狭い（実測236px）ので、
「ひとつだけなら、画面いっぱいに」が
**「ひと」／「つだけなら、画面いっぱいに」**と語の途中で折れた。

`pretty` に変えると、文節を尊重したまま最終行が1語だけになるのも避ける。
**大きな見出し（hero / sec / close）は幅があるので balance のままでよい。**

見つけにくい理由が2つある。**幅で挙動が変わる**ので、
少し違う幅で試すと再現しない。そして行末が「ひと」のように
助詞と同じ字で終わると、機械の検出をすり抜ける。
**目で見るしかない。**

## 生成元

### 一括置換のスクリプトを生成元に当てて、1本を破壊した
複数の `gen_*.py` のリード文をまとめて詰めようとして、
`gen_keiei.py` の**354行を消した**（`toc=[...]` ごと飛んだ）。
本文が三重引用符やカッコをまたぐので、正規表現で切ると閉じ位置を見誤る。
ほか5本も前半だけ畳まれて末尾の文が残っていた。
**生成元は手で直す。** 復旧は `git checkout -- <path>`。

### publish の列に足し忘れると、作り直すたびに静かに剥がれる
`publish.py` には「資料に当てるものは必ずこの列に足す」と書いてある。
それでも `normalize_hero`（扉の大きさをそろえるCSS）が入っていなかった。
生成元から作り直した資料だけが、扉の並びを失って元の姿に戻る。
**しかも検査は通る。** `check_hero` は文字の長さを測っているので、
CSSが剥がれたことは分からない。実際に2本で剥がれていた。

### トップページへの行き先を `../index.html` と書く
資料は `09_role/` の下にも `AX_Table/` の下にも、根の直下にもある。
`../` で書くと根の直下の資料が親を辿ってしまい、
便覧のフッターが行き止まりになっていた。**`/index.html` と書く。**
404の転送表も同じで、`BASE` に GitHub Pages 時代の
`/ozaken-materials/` が固定で書いてあり、古いリンクが無い場所へ送られていた。

### 資料だけ直して、生成元を置き忘れる
資料（暗号化済みHTML）を直しても、`sources/gen_*.py` は古いまま。
次に生成し直したときに、直した内容が丸ごと巻き戻る。
**直したら必ず両方**。`python3 gen_*.py` が走ること、
吐いた断片と公開中の資料の文が一致することまで見る。

### 節への参照を「Section 06」と本文に書かない
後処理が `Section \d+` を見て番号を振り直すので、本文に書いた参照も
一緒に書き換わり、面数が15→17に化けた。**節は題で指す。**

## 構成

### セクションを1本足すと `check()` が落ちる
本文セクションは**奇数本**でなければならず、light/navy が交互で、
最後は navy。1本足すと偶数になる。**足すなら2本、または既存を統合する。**

### 付録セクションを足すと並びの規約が壊れる
`sec-light` / `sec-navy` を名乗るものを1本足すと、本文セクションとして数えられ、
**偶数本・末尾が light** になって `check()` が落ちる。
関連資料は結局、セクションの中に置く小さなチップ（`.xr-chips`）にした。
セクションを増やさないので規約に触れず、話をしている場所にリンクが出る。

### 節を足しても背景の割り当ては崩れない
`data-bg` 属性で持たせているので、あとから挿入しても問題ない。
`apply_bgcycle.py` を当て直せば振り直される。

## 素材

### 会話に添付された画像は、こちらからディスクに保存できない
資料に画像を使うときは、**ユーザーにリポジトリへコミットしてもらう**。
`99_assets/` に置いてもらい、そのパスを参照する。

`pypdf` のテキスト抽出では数値が落ちる。

```python
import fitz
fitz.open(path)[6].get_pixmap(dpi=170).save('/tmp/p7.png')
```

## 検証

### `elementHandle.hover()` がタイムアウトする
ファーストビューの要素はアニメーションで動き続けているため、
Playwright が「安定していない」と判断して待ち続ける。
`page.mouse.move()` に `boundingBox()` の座標を渡す。

### `getComputedTextLength()` は当てにならない
`lines()` が生成する `<text>` は `<tspan>` を複数持つので、
返る値は全行の合計になる。**はみ出し検出には使えない。** 目で見る。

### レンダリング前に `data-reveal` を外す
本文は画面に入るまで透明。スクリーンショットを撮る前に、
`document.querySelectorAll('[data-reveal]').forEach(e => e.classList.add('visible'))`
で可視化する。`shot_figs.mjs` はこれをやっている。
