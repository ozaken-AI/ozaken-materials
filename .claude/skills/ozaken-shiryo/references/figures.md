# 作図関数カタログ

`.claude/skills/ozaken-shiryo/scripts/domain_fig.py` に25種類。すべて同じ形で使う。

```python
from domain_fig import fig_cols
html = fig_cols(items, 'タイトル', 'キャプション', dark=True)
```

- `dark=True` は **navy セクションに置くとき**。忘れると文字が読めなくなる
- `title` は図の見出し、`cap` は図の下の小さな注記（出典はここに書く）
- 返り値は `.figure` を含むHTML。`sec()` の `fig=` にそのまま渡す

## 動きは自動で付く

図版は、画面に入ると**要素が描画順に少しずつ現れる**。
`_fig()` が各要素に印と遅延を振っているので、**自分で書く必要はない**。

動きには2種類ある。**出るときの動き**と、**出たあとも動き続けるもの**。

### 出るとき（一度だけ）

| 印 | 動き | 自動で付く先 |
|---|---|---|
| `a-fade` | 描画順に浮かび上がる | 既定。すべての要素 |
| `a-grow` | 左から伸びる | `fig_bars` `fig_stack` `fig_ranges` の棒 |
| `a-draw` | 線が引かれていく | `fig_donut` の円弧 |
| `a-pop` | 跳ねて現れる | `fig_map` の点 |

`a-pop` だけは中心座標が要るので `style="--o:320px 90px"` を添える。

### 出たあとも（ずっと）

静止画のままだと、投影中に「止まっている資料」に見える。
かといって派手に動くと話の邪魔になるので、**ゆっくり・小さく**動かしている。

| 印 | 動き | 自動で付く先 |
|---|---|---|
| `a-flow` | 破線が線に沿って流れ続ける | `marker-end`（矢印）か `stroke-dasharray` を持つ線 |
| `a-breathe` | 明るさがゆっくり呼吸する（4.2秒周期） | 細い角丸の色帯、塗りつぶした小さな円（半径13未満） |
| `a-pulse` | ゆっくり脈打つ（3.4秒周期） | 塗りつぶした大きめの円（半径13以上）。VSの座など |

判定は `domain_fig._animate()` がやる。矢印を持つ図（`fig_flow` `fig_cycle`
`fig_gap` `fig_issues` `fig_tree` `fig_kpi`）は、**何もしなくても矢印が流れる**。

キーフレームの名前は `oz` で始める（`ozFxIn` `ozFlow` `ozBreathe` `ozPulse`）。
資料ごとに定義の違う名前を借りると、その定義を持たない資料で
`opacity:0` のまま止まり、**要素が丸ごと消える**。実際に矢印が17本の資料から消えた。

自分で指定したいときは、SVGの要素に直接クラスを書けばよい。
`_animate()` は**すでに `a-` が付いている要素には手を出さない**ので、
書いたものがそのまま優先される。

`prefers-reduced-motion` が有効な環境では、すべて静止して表示される。

### 既存の資料に後から入れる

新規は `_fig()` が自動で振るが、昔作った資料には印が無い。

```bash
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_figanim.py
```

古い印を剥がして今の規則で振り直し、CSSと起動スクリプトを補う。
`_animate()` の判定規則を変えたときも、これを流せば全資料に行き渡る。

## いちばん大事なこと：文字数の上限

SVGは自動で折り返さない。`lines()` が指定文字数で機械的に折るだけで、
**行数が箱の高さを超えると、そのまま外にはみ出して隣と重なる**。
コードは通り、ブラウザもエラーを出さない。目で見るまで気づけない。

だから各関数の「入る行数」を守る。迷ったら短く書く。
投影資料なので、短いほうが正しい。

## 並列を見せる

### fig_cols — 3〜4カラム。いちばん出番が多い
```python
fig_cols([(英字ラベル, 名前, 一言, 本文, 差し色0-3), ...], title, cap)
```
- 3〜4個。5個以上は入らない
- **本文は4行まで**。3カラムなら1行あたり約26文字、4カラムなら約19文字
- 「4つの要素」「3つの選択肢」「3つの型」に最適

### fig_orgs — 規模の違う組織や選択肢を、棒の長さつきで並べる
```python
fig_orgs([(名前, 数値, 表示, [箇条1, 箇条2], 位置づけ, 差し色), ...], title, cap, unit='')
```
- 箇条は3つまで、1つ12文字程度

### fig_issues — 横に並べて、連鎖していることを矢印で示す
```python
fig_issues([(短ラベル, ひとこと), ...], title, cap, uid='一意な文字列')
```
- **「壁 1」「壁 2」という固定ラベルが入る。** 課題の連鎖以外には使わない
- ラベルは9文字、ひとことは11文字×2行まで。かなり狭い
- `uid` は必須。同じページに2つ置くと marker の id が衝突する

## 段階・順序を見せる

### fig_ladder — 手順や抽象度の階段。説明が長めでも入る
```python
fig_ladder([(見出し, 補足), ...], title, cap, asc=True)
```
- `asc=True` で下から上へ（積み上がる感じ）、`False` で上から下へ（手順）
- **補足は52文字まで。1行に収める**。超えると箱の外に出る
- 4〜6段が読みやすい

### fig_stairs — レベルの階段。上るほど高くなる形が視覚的に効く
```python
fig_stairs([(レベル表記, 記号, 名前, 製品名, 説明, 差し色), ...], title, cap, note='')
```
- 説明は15文字×3行程度。「5レベル」「4段階」のような話に

### fig_pyramid — 上ほど少ない／希少なものの層
```python
fig_pyramid([(層名, 説明, 差し色), ...], title, cap, left_label='', right_label='')
```

### fig_timeline — 出来事の並び。主体ごとに色を分けられる
```python
fig_timeline([(日付, 主体, 出来事, 意味, 差し色), ...], title, cap, axis='2026年5月')
```

### fig_ranges — 工程表。どのフェーズで何が動くかの帯
```python
fig_ranges([フェーズ名...], [(名前, 開始index, 終了index, 差し色, 補足), ...], title, cap)
```

## 対比・分類を見せる

### fig_gap — 左右の対比。ビフォーアフター、旧と新
```python
fig_gap([(左, 右), ...], title, cap, uid='一意', left_label='いま', right_label='3年後の到達像')
```
- **見出しは必ず内容に合わせて差し替える。** 既定の「3年後の到達像」のまま使わない
- 左右とも22文字×2行まで
- `uid` 必須

### fig_quad — 4象限
```python
fig_quad(x軸ラベル, y軸ラベル, [(見出し, 補足, 危険度0-2), ...4つ], title, cap)
```
- **見出しは34文字（17文字×2行）まで。補足は63文字（21文字×3行）まで**
- 危険度は 0=青 / 1=橙 / 2=赤。色に意味を持たせる
- y軸ラベルに矢印記号を入れると `check()` に弾かれる（回転テキストで向きが壊れるため）

### fig_context — 下から積み上がる4層。文脈やデータの階層に
```python
fig_context([(層名, 具体例), ...], title, cap)
```

### fig_roles — ストラテジスト／アーキテクト／オペレーターの3役
```python
fig_roles([ストラテジストの担当, アーキテクトの担当, オペレーターの担当], title, cap)
```
- この3役の話に特化している。汎用の3分割には `fig_cols` を使う

## 数字を見せる

### fig_bars — 横棒グラフ。金額・比率・件数の比較
```python
fig_bars([(ラベル, 数値, 表示文字列, 補足, 強調0-2), ...], title, cap, unit='', note='')
```
- **表示文字列は短く。** 棒の右に置かれるので、最大値の項目は特に短くする
  （最長の棒は x=750 まで伸びる。残り約140pxしかない → 12文字程度が限界）
- **補足は1行（約30文字）まで**。2行になると次の行と重なる
- 強調は 0=青 / 1=橙 / 2=赤

### fig_sheet — 表。`<table>` が禁止されているのでSVGで組む
```python
fig_sheet([列名...], [[セル...], ...], [列幅の比...], title, cap, badge='記入例', note='')
```
- 列幅の比は合計1.0。文字数に応じて配分する
- 行の高さは中身に応じて自動で伸びるので、**唯一はみ出しを気にしなくていい図**
- `badge` は左上の小さなラベル。「記入例」「2026年8月時点」など
- ワークシートの記入例、料金表、比較表に

### fig_kpi — 上位指標から下位指標への分解
```python
fig_kpi(頂点の指標, [(中位指標, [下位指標, ...]), ...最大3本], title, cap)
```

## 手順・流れを見せる（つづき）

### fig_flow — 横一列のプロセス。矢印でつなぐ汎用の形
```python
fig_flow([(見出し, 補足), ...], title, cap, uid='一意', note='')
```
- 3〜5個。番号入りの丸が上に付く
- 見出しは1〜2行、補足は3行程度。`uid` 必須
- `fig_issues` と違い「壁」という固定ラベルが無いので、**手順・工程はこちらを使う**

### fig_cycle — 円環。終わりが始まりに戻る話に
```python
fig_cycle([(見出し, 補足), ...], title, cap, center='中心の言葉', uid='一意')
```
- 4〜6個。PDCA、フィードバックループ、改善のサイクル
- 見出しは12文字、補足は16文字×2行まで。箱が小さいので短く
- `center` に「何を回しているのか」を置くと締まる
- 箱は楕円に並び、あいだを矢じり付きの弧がつなぐ。16:9の面で
  横を使い切るための形。**紺の面に置くときは `dark=True` を必ず渡す**
  （渡し忘れると白い箱が紺地に浮く。業務変革大全で4面やった）

## 数字を見せる（つづき）

### fig_stats — 大きな数字。**投影でいちばん効く形**
```python
fig_stats([(数値, 単位, 何の数字か, 出典や補足, 差し色), ...], title, cap)
```
- 3〜4個。数値は文字数で自動的にサイズが変わる（4桁までは特大）
- 「1,500本の記事」「年300回の登壇」「80%削減」のような、
  **一目で効く数字**を並べるときに使う。説明はカードに逃がす

### fig_donut — 構成比。1つの全体を分ける
```python
fig_donut([(名前, 数値, 補足), ...], title, cap, center='100%', note='')
```
- 3〜5個。数値の合計を100%として自動計算する
- 凡例は右に縦積みされ、%も自動で出る
- 6個以上は色が足りなくなるので `fig_bars` へ

### fig_stack — 積み上げ棒。複数の対象を内訳ごと比べる
```python
fig_stack([(対象名, [内訳の数値, ...]), ...], [内訳の名前, ...], title, cap, unit='')
```
- 内訳は3〜4系統まで。凡例が上に出る
- 「A社・B社・C社の使い方の違い」のような、
  **合計も内訳も同時に見せたいとき**に

## 分類・判断を見せる（つづき）

### fig_matrix — 行×列の格子。どこが該当するかを印で示す
```python
fig_matrix([列名, ...], [(行名, [各列の値, ...]), ...], title, cap, note='')
```
- 値に `○ ◎ △ × －` を入れると色が付く（緑・青・橙・赤・灰）
- 短い文字列も入る。行の高さは自動
- 「部署 × 用途」「ツール × 機能」の可否表に

### fig_versus — 二項対立。どちらを選ぶかの話
```python
fig_versus((左の見出し, ひとこと), (右の見出し, ひとこと),
           [(観点, 左の内容, 右の内容), ...], title, cap)
```
- 左が青、右が赤で固定。**赤い側が「注意して選ぶべき方」**になるよう並べる
- 各セルは25文字×2行まで
- `fig_gap`（時間の前後）と違い、**同時に存在する2択**に使う

### fig_check — 判定リスト。やること・やらないこと
```python
fig_check([(True/False/None, 見出し, 補足), ...], title, cap, note='')
```
- `True`=○緑 / `False`=×赤 / `None`=－灰
- 見出しは34文字、補足は62文字まで。行の高さは自動で伸びる
- ガイドライン、可否の一覧、チェックリストに

## 構造を見せる（つづき）

### fig_tree — 階層ツリー。2段まで
```python
fig_tree(頂点の名前, [(枝の名前, [葉, ...]), ...], title, cap, uid='一意')
```
- 枝は2〜4本、葉は各3つまで
- 分類・組織・役割の構造に。KPIの分解は `fig_kpi` のほうが適する

### fig_map — 2軸に点を置く。4象限より自由度が高い
```python
fig_map(x軸ラベル, y軸ラベル, [(名前, x0-100, y0-100, 差し色, 補足), ...],
        title, cap, corners=[(x, y, 説明), ...])
```
- 点は3〜6個。座標は0〜100で指定する
- `corners` で「この隅は何を意味するか」を書ける
- **どれから手を付けるか**を示すのに強い（導入のしやすさ × 効果の大きさ）
- y軸ラベルに矢印記号は入れない

## 選ぶときの指針

| 見せたいもの | 使う |
|---|---|
| 3〜4個の並列概念 | `fig_cols` |
| 手順・段階 | `fig_ladder`（説明長め）／`fig_stairs`（レベル感） |
| 旧と新の対比 | `fig_gap` |
| 2軸の分類 | `fig_quad` |
| 数値の比較 | `fig_bars` |
| 表・記入例 | `fig_sheet` |
| 時間の流れ | `fig_timeline` |
| 工程の重なり | `fig_ranges` |
| 課題の連鎖 | `fig_issues` |
| 手順・工程（汎用） | `fig_flow` |
| 繰り返すサイクル | `fig_cycle` |
| 効かせたい数字 | `fig_stats` |
| 構成比 | `fig_donut`（1つの全体）／`fig_stack`（複数の比較） |
| 可否・該当の一覧 | `fig_matrix` |
| 2択の比較 | `fig_versus` |
| やる・やらない | `fig_check` |
| 階層・分類 | `fig_tree` |
| 優先順位の位置づけ | `fig_map` |

**同じ関数を3回以上続けない。** 9セクションなら、
`fig_gap → fig_stats → fig_sheet → fig_cols → fig_bars → fig_flow → fig_matrix → fig_versus → fig_check`
のように散らす。形が変わるだけで、聴講者の集中は保たれる。

**冒頭には `fig_stats` か `fig_gap` が効く。** 数字か対比で「なぜこの話をするのか」を
1枚で立てられると、そのあとの各論が入りやすくなる。

新しい形が必要になったら、`domain_fig.py` に足す。
既存の関数を無理に流用して、意味の合わないラベルを残すほうが害が大きい。
