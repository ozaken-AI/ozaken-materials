# おざけん資料の作り方

## この資料が置かれる状況を、まず頭に入れる

作った資料は、**プロジェクターかモニターに映される**。読み物ではない。
おざけんが壇上で話しながら、聴講者はスクリーンを見る。手元では読まない。

ここから、守るべきことがほぼ全部導ける。

- **図が主役、文章は従**。1セクションに必ず1つ以上の図版を置く。図が無いセクションは、投影したときに「壁一面の文字」になる
- **1画面に1メッセージ**。セクションの見出しを見ただけで、そのセクションの主張が伝わること
- **後ろの席から読める文字量**。カードの本文は2〜4行。図版の中の文字は、後述の上限を必ず守る
- **数字と固有名詞を落とさない**。投影資料の説得力は、具体の密度で決まる

**ファーストビューは画面を占有する**（`min-height:100svh`）。投影したとき、
表紙として1枚で成立させるため。高さの上限は設けない。

**表紙の地の色は、index.html とまったく同じ**。単色の紺だと平坦に見えるので、
上からの光・右下の赤み・斜めの三段グラデを重ねて奥行きを出している。
資料ごとに違う紺を使うと、並べたときに「別のサイト」に見えてしまう。
`apply_herofx.py` が当てるので、自分で書かない。
（写真を敷いた AX Table のヒーローだけは、写真が主役なので対象外）

**面ごとに背景色が変わる**。明るい面・暗い面という骨格の中で、それぞれ3段の色味が循環する。
同じ2色が交互に出るだけだと、送っていくうちに景色が変わらない資料に見えて、
聴講者が「いま何枚目か」を見失う。`apply_bgcycle.py` が自動で割り当てるので、
本文を書くときに意識する必要はない。

「文字が多い」と言われる資料は、たいてい**図版で語れることを文章で語っている**。
書きたくなったら、まず「これは図にできないか」を考える。

## 手順

### 0. 作りはじめる前に、1つだけ聞く

**資料を作る依頼を受けたら、着手する前に必ずこれを聞く。**
表の資料でも裏資料でも、講座でも同じ。

> 1. **資料だけ作成**
> 2. **ワークシート配布あり**（書き込むPDFを添える）

あとから足すこともできるが、**ワークシートを付けるなら構成が変わる**。
書かせる前提の資料は、図版を「見せる図」ではなく「写して埋める型」に寄せ、
セクションの終わりに手を止める場所をつくる必要がある。
最初に決めておかないと、出来上がってから作り直すことになる。

聞き方は `AskUserQuestion` で2択。ほかのことは聞かなくてよい
（テーマ・置き場・パスワードは、こちらで決めて進めてよい）。

### 1. 素材を読み、事実を拾う

PDF・記事・議事録が渡されたら、まず全部読む。
PDFは `pypdf` でテキストを、図表は `pymupdf` でページ画像にして目で読む
（表が画像で埋め込まれていることが多く、数値はそこにある）。

```python
import fitz
fitz.open(path)[6].get_pixmap(dpi=170).save('/tmp/p7.png')   # Readツールで見る
```

拾うべきは、**数値・固有名詞・日付・引用できる一文**。
「重要そうな概念」より「6か月分」「$0.01」「最大80%」のほうが、投影では効く。

出典が外部資料なら、図版のキャプションに必ず書く。
自分で計算した値（換算・試算）は、原典の数値と区別できるように明記する。
これは誠実さの問題であり、おざけんが壇上で「これは私の試算です」と言えるようにするためでもある。

**鮮度の落ちる数字には、確認日を書く。** 料金・プラン名・モデル名は数か月で変わる。
「2026年8月時点」と入れておけば、古くなっても資料が嘘にならず、
壇上で「いまは変わっているかもしれません」と補足できる。
公式ページに到達できないときは、**二次情報にもとづくことも明記する**。
黙って断定するより、出所を示して読む側に判断を委ねるほうが強い。

### 2. 既存の資料と突き合わせる。ここを飛ばさない

**新しい資料は、更地に建てるのではない。** 68本の資料がすでにあり、
そのほとんどが同じ概念に触れている。何も見ずに書くと、
同じ話に別の説明がつき、同じ数字が別の値になる。
おざけんは同じ聴衆に何本も見せるので、**食い違いはそのまま信用の問題になる**。

書き始める前に、必ず調べる。資料は暗号化されているので `grep` では読めない。

```bash
cd .claude/skills/ozaken-shiryo/scripts
OZAKEN_PW=マスター python3 find.py 暗黙知              # 全資料の本文からさがす
OZAKEN_PW=マスター python3 find.py 1クレジット --full   # 前後を長めに出す
OZAKEN_PW=マスター python3 find.py --heads --in 05_drive # 見出しだけ一望する
OZAKEN_PW=マスター python3 crossref.py map            # 概念と正典の対応
```

調べた結果は、こう扱う。

- **概念の定義は、正典に合わせる。** `crossref_data.py` に正典が決まっている概念は、
  そこでの説明と揃える。言い回しまで真似る必要はないが、**主張が割れてはいけない**
- **数字は、既存の資料と同じ値を使う。** 出典と確認日も引き継ぐ。
  新しい数字に更新するなら、**古い資料のほうも直す**。片方だけ新しいのがいちばん悪い
- **説明の重複は、正典に寄せる。** 同じ概念を1から説明し直すのではなく、
  この資料に必要な分だけ書いて、深掘りはリンクに任せる
- **既存の主張と食い違う結論に至ったら、書く前に立ち止まる。**
  新しい事実で考えが変わったのなら、それは既存の資料を直すべき合図。
  黙って新しい資料にだけ新説を書くと、どちらが本当か分からなくなる

新しい資料が、ある概念の**いちばん詳しい説明**になるなら、
`crossref_data.py` に正典として登録する。以後、他の資料からそこへリンクが張られる。

```python
'Copilot Credits': ('03_tools/copilot-credits.html',
    ['Copilot Credit', 'クレジット'], '使った分だけ課金される仕組み'),
```

### 3. 骨格を決める

**セクションは、飛ばされる前提で作る。**
おざけんは会場の反応を見ながら順番を変え、要らないところは飛ばして話す。
だから「1本目から順に読まないと分からない資料」は、本番で使えない。

- 各セクションは、**そこだけ映しても意味が通る**こと
- 前のセクションを指す言葉（「前述の」「先ほどの」）を本文に書かない
- 数字や用語は、必要なセクションで**その都度**出す。初出でしか説明しないと、
  そこを飛ばされた瞬間に伝わらなくなる
- セクションの見出しだけで主張が分かること。これは飛ばし読みへの備えでもある

本数は内容が要求するぶんだけ置けばよく、**多い少ないを気にしなくていい**。
飛ばせる資料であれば、多い分には困らない。

### 4. 並びを決める

本文セクションは**奇数本**（7本か9本が扱いやすい）。
`sec-light` と `sec-navy` を交互に並べ、最後は必ず navy で締める。
この制約は `check()` が機械的に見ているので、外れると公開できない。

構成の型としてよく効くのは、この流れ。

1. **なぜ今それが問題なのか**（前提の共有。対比の図が効く）
2. **全体像**（分類・構造。並列の図）
3〜7. **各論**（1セクション1論点。数値・手順・境界線）
8. **落とし穴／誤解**（ここが講演で一番ウケる）
9. **明日から何をするか**（行動に翻訳する）
   → 締めの navy セクションで、一段高い視点に引き上げる

### 5. 図版を選ぶ

25種類の作図関数が `.claude/skills/ozaken-shiryo/scripts/domain_fig.py` にある。
**同じ形式を3回以上続けない**。飽きるし、内容の違いが見えなくなる。

選び方と、それぞれの文字数上限は `references/figures.md` を読むこと。
**文字数上限は飾りではない**。SVGは自動で折り返さないので、
上限を超えた文字は箱からはみ出し、隣の行に重なる。
実際に何度もこれで壊れている。

**図版は自分で動く。** 画面に入ると要素が描画順に立ち上がり、
そのあとも矢印や破線は流れ続け、色帯や点はゆっくり呼吸する。
投影しっぱなしにしても「止まった絵」に見えないための仕掛けで、
`_fig()` が自動で振るので本文を書くときに意識する必要はない。
規則は `references/figures.md` の「動きは自動で付く」に書いてある。

### 6. 組んで、検査する

本文フラグメントを書き、`publish.py` に渡す。組版・検査・演出・暗号化・台帳登録・掲載まで一括で通る。

```bash
cd .claude/skills/ozaken-shiryo/scripts
OZAKEN_PW=マスター python3 publish.py \
    /tmp/body_foo.html 03_tools/foo.html \
    --list "Foo入門 ─ 現場で効く3つの型"
```

`--backstage` を付けると index ではなく裏資料置き場に載る。
`--list` を省くと一覧に載せず、生成と台帳登録だけを行う。

**出力先のパスは英語だけで書く。** URLをそのまま人に渡すので、
日本語のファイル名だとシェアしたときに `%E7%94%9F%E6%88%90…` に化ける。
フォルダは `NN_english`、ファイルは `lowercase-hyphen.html`。
題を直訳せず、内容が分かる短い英語にする（`ai-coe.html` `agent-budget-taxi.html`）。
すでにある資料と紛らわしいときは、末尾に `-v2` のような区別を足す。

裏資料の置き場所は3つあり、**どのフォルダに出すかで載る節が決まる**。

| フォルダ | 裏資料置き場の節 | 何を置くか |
|---|---|---|
| `Udemy/` | Udemy講座 | オンライン講座の教材。**受講後に手が動く**ところまで持っていく |
| `AX_Table/` | AX Table | イベントの連続セッション。進行台本の型で組む |
| `Training/` | 法人研修 | 企業向けの研修カリキュラム案と、当日の進行資料 |
| （それ以外） | スポット講演・セミナー | 単発の講演。表の分類フォルダに置いてよい |

節を増やすときは `publish.py` の `BACKSTAGE_SECTIONS` と、
`oz_root.BACKSTAGE_DIRS` の2か所だけ直す。走査する道具はすべて後者を見ている
（昔は8本のスクリプトに同じ組を書いていて、`Training` を足したときに5本壊した）。

**講座は、講演と設計が違う。** 講演は「その場で腹落ちさせる」で終わってよいが、
講座は受講者が一人で観る。だから各セクションに演習を置き、最後を実行計画で締める。
**裏資料限定の機能が、そのまま演習になる** ── 持ち帰りキットが手を動かす欄に、
確認テストがセクション末の理解度チェックになる。

**数字を扱う資料には「更新されます」と書く。** AIと雇用の統計は数か月で景色が変わるが、
講座の動画は撮り直せない。**腐る数字はHTML側に置き、そこだけ差し替える**設計にしておくと、
動画を撮り直さずに鮮度を保てる。表紙のリード・数字の面のキャプション・
最初のセクションのカードの3か所に、
「新しい統計が出るたびに差し替えます。URLは変わりません」と明記する。
壇上でも「数字は更新されるので、この資料を見てください」と言えるようになり、
**URLを配ること自体が価値**になる。

**尺（何分）は資料に書かない。** 収録や進行のたびに変わるので、書くと必ず食い違う。

**研修の資料を `AX_Table/` に出さない。** 別物が同居して、
一覧で何がイベントの資料なのか分からなくなる。

**裏資料置き場に、個別パスワードは書かない。** この一覧は投影することがあり、
書いておくと全資料の鍵が一度に映る。パスワードは資料を開いて `qr` で出す（後述）。

**裏資料置き場は、新しいものが上。** 講演の前に開くのはたいてい直近の資料で、
終わった資料は下に積み上がって一覧として残る。`publish.py --backstage` は
新しいカードを節の先頭に差し、節ごと作るときはヒーローのすぐ下に置く。
カード番号は節の中で振り直されるので、**`01` が常にその節のいちばん新しいもの**になる
（AX Table だけは番号がセッション番号なので触らない）。
明暗と背景の段も `retone()` が付け直すので、並べ替えても色は続かない。

本文フラグメントの先頭には、必ずメタ行を置く。

```html
<!--META title=資料タイトル ─ 副題 | desc=検索結果に出る一文。-->
```

### 7. 目で見る。ここを飛ばさない

**図版は必ずレンダリングして確認する。** コードが通ることと、読めることは別。
文字のはみ出し・重なり・見切れは、コードからは見えない。

```bash
npm i playwright-core          # リポジトリ直下で一度だけ。ブラウザ本体は導入済み
OZAKEN_PW=マスター node .claude/skills/ozaken-shiryo/scripts/shot_figs.mjs 03_tools/foo.html /tmp/figs
```

各図版のPNGが出るので、Readツールで1枚ずつ見る。見るべきは4点。

- 箱から文字がはみ出していないか
- 行が重なっていないか
- 右端で数値が見切れていないか
- **図のラベルが内容と合っているか**（汎用の作図関数は「壁1」「3年後の到達像」のような
  固定文言を持つことがある。意味が合わない図を流用しない）

### 8. 受講者の目で評価する。作った本人の目では見えない

**`ozaken-hyoka` スキルを必ず使う。** 自分で組んだ資料は、
どうしても「書いたこと」を基準に見てしまい、
**会場の後ろから3列目に座っている人**にどう見えるかが分からなくなる。

見るのは、機械が見られないところ。

- 全体を貫くメッセージが1本あるか（表紙と締めが同じことを言っているか）
- 各セクションに、**おざけんにしか言えない見方**があるか。一般論の再掲になっていないか
- 分類を出している面は、**本当にMECEか**（軸が混ざるのがいちばん多い失敗）
- 講演資料として面白いか。眠くなる面が無いか
- 図版のかたちや色が単調でないか

```bash
cd .claude/skills/ozaken-shiryo/scripts
OZAKEN_PW=マスター python3 deck_stats.py 03_tools/foo.html    # 面ごとに数える
OZAKEN_PW=マスター node shot_secs.mjs 03_tools/foo.html /tmp/secs  # 面ごとに撮る
```

**★2以下が付いた軸は、直してから公開する。** 評価は出して終わりではない。

### 9. つなぎ直す

出来た資料は、まだアーカイブから孤立している。最後に必ずつなぐ。

```bash
cd .claude/skills/ozaken-shiryo/scripts
OZAKEN_PW=マスター python3 crossref.py preview 新しい資料   # 何が並ぶか確かめる
OZAKEN_PW=マスター python3 crossref.py apply               # チップを挿入
OZAKEN_PW=マスター python3 crossref.py check               # 数字の食い違いを洗う
OZAKEN_PW=マスター python3 crossref.py matrix              # マトリクスを作り直す
```

`check` は「同じ概念の周辺に、資料ごとに違う数値が出ている」箇所を並べる。
**機械は食い違いを見つけるだけで、どちらが正しいかは判断しない。**
出てきたものは目で確かめて、古いほうを直す。

マトリクス（`mx`）で、新しい資料の行に印が付いていることを見る。
一つも付いていなければ、どこともつながっていないということ。
本当に独立した話題ならそれでよいが、たいていは
`crossref_data.py` に拾う語が足りていない。

## 書きぶり

**タイトル**は `<br>` で2行に割る。ファーストビューの演出が、
「」の中か英字のかたまりを自動で赤く強調するので、そこを意識して言葉を置く。

```
Copilot Credits 完全ガイド<br>「使った分だけ」が始まった
       ↑ 「使った分だけ」が赤くなる
```

**セクション見出し**は、体言止めより述語で言い切る。
「Copilot Credits の概要」ではなく「1クレジット＝$0.01。買い方は2つしかない」。
投影されたとき、見出しだけで主張が伝わる。

**カード**は3枚が基本。`<span class="mth">短いラベル</span>見出し` の形にすると、
ラベルが目印になって、聴講者が話の位置を見失わない。

**締めのセクション**では、事実の要約をしない。
資料全体を1段上の視点から言い直す。おざけんの資料の価値はここに出る。
「この変化の本質は値上げでも値下げでもない。AIの使い方が、はじめて金額として見えるようになったということだ」のように。

## わかりやすさのレギュレーション

**この資料は、頭から順に読まれるとはかぎらない。**
投影中はカードが1枚だけ写る。スクロールしていて図だけ目に入る。
講座の受講者は、前の面を覚えていない。
だから前提は、**「箱1つだけを読んだ人に通じるか」**。

実際に出た事故は、どれも同じ形をしていた。

| 書いたもの | 何が抜けたか |
| --- | --- |
| 「6月の増加ペースは……」 | **何の**増加か。書いた本人の頭にはある |
| 「2026年7月13日、200名超が署名した」 | **何の**声明か。題名だけでは中身が分からない |
| 「ダロン・アセモグルまで名を連ねた」 | **誰**なのか。知っている人にしか効かない |
| 「BLSはソフト開発職を……」 | 略語のまま置いた |
| 「この矛盾を放置したまま」 | **どの**矛盾か。前のカードにしかない |
| 「Fig.7 の水準は」 | 節を足し引きしたあと、参照だけが残った |

守る形は5つ。どれも、書くときに一手間かけるだけで消える。

- **数量には、必ず主語を付ける**。「6月の増加ペース」ではなく
  「米国の雇用者数（非農業部門）の6月の増加ペース」。
  何の数字かが箱の中で分からないなら、その数字は置かない
- **固有名詞は、正体とセットで出す**。人名なら肩書き
  （「MITの経済学者、ダロン・アセモグル」）、組織なら何をしている組織か、
  声明や調査なら何を言っているものか。**名前だけ置いても、権威は伝わらない**
- **略語の初出は「日本語名（略語）」**。`ACS＝アメリカ地域社会調査` のように
  `＝` で繋いでもよい。AI・IT・DX のように日本語の記事にそのまま出る語は例外
- **カードを指示語で始めない**。「この」「その」「これ」で始めると、
  そのカードだけを見た人には指す先が無い。名詞から始める
- **図の参照は、節を動かしたら必ず数え直す**。存在しない Fig. を指したまま
  公開すると、読者はスクロールして探し、見つからず、資料ごと信用しなくなる

**難易度の基準は「大学生が初見で止まらないこと」。**
中央値、不完全雇用率、就業者比率、職務記述書のような語は、
その場で1行の説明を添える。専門家に向けて書いているのではない。

これらのうち機械で拾える形は `check_wakaru.py` が見ていて、
`publish.py` が公開時に必ず表示する（**公開は止めない**。
止めると、直す機会ごと失うため）。全資料の一覧は
`OZAKEN_PW=… python3 lint_all.py --wakaru`。

## 色とフォント

**規定を外れた色・書体を使うと、公開できない。** `check()` が機械的に弾く。
資料ごとに見た目がバラつく最大の原因は、その場の思いつきで色を足すことなので、
ここは意図的に厳しくしてある。

覚えておくべきは3つ。

- **色は装飾ではなく意味**。赤は「危険」か「ここが要点」だけ。**1画面に1箇所まで**。
  ただ目立たせたいだけならAMBER（`#c9762f`）を使う
- **暗い面の赤は、明るい面と同じ色では沈む**。`text-red` と書けば、
  明るい面では `--red`、暗い面では `--red-bright` が出るようにしてある。
  面ごとに色を書き分けない
- **書体は3つだけ**。明朝＝主張、ゴシック＝説明、英字＝ラベルと数値。
  **SVGの中は必ずゴシック**（明朝は投影で線が飛ぶ）
- **背景色は自分で書かない**。面ごとの色は `apply_bgcycle.py` が割り当てる

全トークンの一覧と役割は `references/tokens.md`。**色を書く前に読む。**

## 守られている約束（check が見ている）

- 本文セクションは奇数本、light/navy が交互、最後は navy
- `<table>` は使わない（表はSVGで組む。`fig_sheet` がある）
- CTAボタン（`btn-primary` など）を置かない
- `.take`（大きな引用）は2つまで
- SVGはXMLとして妥当であること、`marker` の id が重複しないこと
- 回転させたテキストに矢印記号（↑↓←→）を入れないこと
- **規定外の色・書体が無いこと**

これとは別に、`check_wakaru.py` が**わかりにくさ**を見る。
主語の抜けた数量、肩書きのない人名、説明のない略語、指示語で始まるカード、
存在しない図への参照。**こちらは公開を止めないが、必ず表示される。**
表示されたのに直さなかったものは、そのまま読者に届く。

`<b>` や `<br>` はHTML本文では使えるが、**SVGの中では使えない**。
`esc()` を通るのでタグがそのまま文字として出てしまう。

## 鍵とパスワード

各資料は3本の鍵で開く。

- **マスター** … おざけん本人だけが持つ
- **共通** … 全資料に共通。まとめて何本も渡すとき用。**資料だけに付ける**
- **個別** … その資料だけ

`publish.py` が個別パスワードを生成し、**passwords.html**（マスター専用の暗号化ページ）に
記録する。

**道具のページには、共通パスワードを付けない。** マスターだけで開く。

| ページ | なぜマスターだけか |
|---|---|
| `passwords.html` | 全資料の個別パスワードが載っている |
| `backstage.html` | 裏資料の置き場。どこに何を出したかが全部見える |
| `matrix.html` | 資料 × 概念の全一覧。アーカイブの構造がそのまま渡る |

共通パスワードは「資料を何本かまとめて渡す」ための鍵なので、
渡した相手にこの3枚まで開かれると、**渡していないものまで全部渡ることになる**。
`check_pw.py` が実行のたびに見ていて、余分な鍵が付いていたら警告を出す。

### 裏資料の個別パスワードは、その資料の芯になる1語にする

会場で読み上げ、聴いている人がその場でスマホに打つ。だから `--pw` で必ず指定する。

```bash
OZAKEN_PW=マスター python3 publish.py /tmp/body.html Training/foo.html \
    --backstage --pw bunkai --list "…"
```

| | |
|---|---|
| 形 | **小文字の英字だけ・1語・4〜10文字**（数字も記号もハイフンもなし。Shiftを押させない） |
| 選び方 | その日いちばん持ち帰ってほしい言葉。`bunkai`（業務を分解する）`soshiki`（組織）`rollout`（本番化） |
| ローマ字か英語か | **綴りが割れる語は英語に逃がす。** 本番化は honban / homban と割れるので `rollout`。分解・組織は一意に書けるのでローマ字 |
| 重複 | アーカイブ全体で一意。`publish.py` が台帳を見て弾く |

**ランダムな文字列にしない。** 読み上げると必ず聞き返されるし、打ち間違えても本人が気づけない。
それより大きい理由として、**1語にすると打つこと自体がその日の主題の復唱になる**。
100人が同時に「bunkai」と打てば、その言葉は指を通って残る。パスワードを教材として使える。

強度を落としている感じがするが、そもそも**共通パスワードで全資料が開く**ので、
個別パスワードは秘密を守るためのものではなく「誰に何を渡したか」の目印。
覚えやすさに全振りしてよい。
（その共通鍵も、資料にしか付いていない。置き場と台帳とマトリクスは開かない）

付け替えるときは `lockbox.add_password` → `remove_password` の順で。
**マスターと共通の鍵はそのまま生き、本文の再暗号化も起きない。**
そのあと `apply_qr.py refresh` を忘れないこと（QR画面にパスワードが焼いてある）。

## 既存資料を直すとき

本文を作り直すときは、**新規と同じ道を通す**。

```bash
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/publish.py \
    /tmp/body_foo.html 05_drive/foo.html --update
```

`--update` は「組む → 検査 → 演出を注入 → `lockbox.encrypt` で書き戻す」。
**鍵は作り直さないので、配布済みのパスワードはそのまま使える。**

`build_page.build` だけで組み直してはいけない。`.lede` や `.mth` のCSSは
`publish` 側で足しているので、**導入文とカード見出しのチップが全部素の文字になる**。
実際にやった。差し替えのあとは `crossref.py apply` も通す（チップは作り直しで消える）。

**手で差し替えるなら `lockbox.encrypt`。鍵はすべて維持される。**
`lockbox.create` は鍵を作り直すので、配布済みのパスワードが死ぬ。

セクションを1本足すと**偶数になって `check()` が落ちる**。
足すなら2本、または既存を統合する。図番号と面番号は
生成側で振り直すようにしておくと、あとから足しても崩れない。

演出やCSSを直したときは、既存の全資料にも当て直さないと見た目が揃わない。

```bash
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/reapply.py herofx   # herofx / keynav / spacing / bg / all
```

## 配布するPDFを作るとき

index の「無料でプレゼント」に置くPDFは、**暗号化せず、HTMLから焼く**。
組み立てのソースは `99_assets/pdf-src/` に置く。あとで直せるようにするため。

```bash
python3 99_assets/pdf-src/business-transformation-guide.py            # HTMLを書体フォルダに書き出す
node .claude/skills/ozaken-shiryo/scripts/make_pdf.mjs \
     /tmp/ozaken-ogp-fonts/bpt.html 04_practice/business-transformation-guide.pdf
```

**配布物は、資料の中からダウンロードできるようにする。** `page_parts.dl()` が
「FREE DOWNLOAD」の枠を出す。CTAボタン（`btn-primary`）は `check()` に弾かれるので使わない。

```python
from page_parts import dl
A(sec(..., fig=図版 + dl('career-strategy-worksheet.pdf',
                        'ワークシート（A4・4ページ）', '説明。')))
```

**リンク先のPDFは、暗号の外に置かれる。** 資料そのものは鍵で守られるが、
PDFは公開URLで誰でも取れる。だから**個別パスワードを刷った紙をここに置かない**。
配るなら2種類焼く ── 公開版（パスワードなし・「講座の中でお伝えします」）と、
配布版（パスワードあり・Udemyの教材リソースや当日配布に使う）。
`99_assets/pdf-src/career-worksheet.py` が両方を書き出す例。

**書き込むワークシートだけは A4縦（`a4p`）で焼く。** 投影物ではなく、
印刷して手で書くもの。横長の紙に手書きの欄を並べても、実際には使われない。
`99_assets/pdf-src/career-worksheet.py` が例。**表紙にQRと個別パスワードを載せる**と、
その紙自体が「いつでも最新版が開くURL」の配り物になる。

**それ以外の配布用PDFは、例外なく16:9（338.67mm × 190.5mm）で焼く。** 投影とスライド共有を
前提にした配布物なので、A4横だと共有先で必ず余白が出る。`make_pdf.mjs` の既定が
16:9なので第3引数は省く。**`a4` を渡す道は残してあるが、ユーザーがA4と明示した
ときだけ。** 1ページ1テーマ。図版は `domain_fig` の `<svg>` だけを抜いて使う
（`.figure` の枠ごと入れると、PDFでは枠が二重に見える）。
**書体は file:// で読ませるので、HTMLは書体フォルダの中に書き出す。**

## 持ち帰りキット（裏資料限定）

**HTMLで配る意味は、渡したあとに使えることにある。** PDFなら投影して終わりだが、
HTMLなら、その場で入力して・保存して・コピーできる道具を仕込める。
講演や研修が終わったあとにURLを渡すと、**受け取った人がそのまま使い続けられる**。

**表の資料には置かない。** 不特定多数が読む解説資料に入力欄があっても使われない。
裏資料は渡す相手が決まっているので、その相手の業務に合わせた道具を仕込める。

本文フラグメントに印を書くだけで、`apply_kit.py` が仕掛けを入れる。
印が無いページには何も起きないので、`compose()` を通せば自動で判定される。

```html
<div class="kit" data-kit="prompt" data-title="頼み方を組み立てて、コピーする"
     data-note="入力はこの端末の中だけに残ります。どこにも送信されません">
  <div class="kit-f" data-label="① あなたは誰か" data-ph="法人向け保険の営業担当"></div>
  <div class="kit-tpl">わたしは{1}です。&#10;お願いしたいこと：{2}</div>
</div>

<div class="kit" data-kit="check" data-title="任せていいか、その場で確かめる">
  <div class="kit-i" data-w="2">週に何度もやっている</div>
  <div class="kit-r" data-min="7">今週、ここから試せます</div>
</div>
```

- `prompt` … 欄を埋めると依頼文ができる。コピー／名前を付けて保存。
  **保存できることが「点から線へ」の実演になる**ので、その説明をしている資料に置くと効く
- `check` … 重みつきの点数と、次に手を付ける項目が出る

**保存先はブラウザの中（localStorage）だけ。どこにも送らない。**
資料は暗号化されて配られるので、開いた本人の端末に閉じる。
この一文は `data-note` にも必ず書く。書いていないと、企業では使ってもらえない。

## 確認テスト（裏資料限定）

企業講演・法人研修では、**聴いて終わりにさせないことが価値になる**。
講演の最後に「画面を3回たたいてください」と伝えると、受講者はその場で、
自分のスマートフォンから確認テストを開ける。理解度が本人に返り、
外した問題については「どのパートを見直すか」まで出る。

`apply_quiz.py` が仕掛ける。印が無いページには何も起きないので、
`compose()` を通せば自動で判定される。

**問題は資料の本文に混ぜない。** 本文フラグメントの**いちばん最後、
最後の `</section>` より後ろ**に置く。テストは隠しコマンドで出るものであって、
読み物としての資料の一部ではない。セクションの中に入れると、
コピーや印刷のときに混ざる。

```html
<div class="quiz" data-title="確認テスト"
     data-sub="今日の90分が身についているか、6問で確かめます">
  <div class="qz-q" data-a="2" data-ref="パート1　AIの主語が、人からAIに変わった">
    <div class="qz-t">AIエージェントが、これまでのAIと違うのはどこですか。</div>
    <div class="qz-o">答えの精度が上がったこと</div>
    <div class="qz-o">主語がAIに移り、手順をAI自身が回すこと</div>
    <div class="qz-w">これまでは、人が聞いてAIが答える形でした。</div>
  </div>
  <div class="qz-res" data-min="5">よく掴めています。</div>
</div>
```

- `data-a` … 正解の選択肢が何番目か（1から数える）
- `data-ref` … どのパートの話か。外したときに「見直す先」として結果に並ぶ
- `qz-w` … 選んだ直後に出る一言。**なぜそうなのか**を短く。ここが講義の続きになる
- `qz-res` … 点数ごとの講評。`data-min` 以上のときに出る（高いものが優先）

**合言葉は置かない。** 開き方そのものが隠しコマンドなので、
その上にもう一枚パスワードを挟むと、会場での説明が長くなるだけになる。

| | どこで効くか |
|---|---|
| 画面を3回たたく | **スマートフォン向け**。どこでもいい。そのまま始まる |
| `test` と打つ | キーボードのある端末向け。どこにも触れずに打つだけ |
| URLに `#test` | あとからメールで案内するとき用 |

**打って開くコマンドは、`apply_keynav.py` の2文字を内側に含む。**
`th st pr ti qa ma ur go en pw mx` は投影画面へのショートカットなので、
`test` はその途中の `st` で index に飛んでしまう。
keynav 側（v4）に「`test` / `quiz` を打ち終えたときは2文字を見送る」ガードを入れて避けている。
**新しいコマンドを足すときは、この `LONG` にも足す。**

問題は**5〜7問**。多いと最後まで行かない。

**難易度は「知っているか」ではなく「見分けられるか」に置く。**
用語を言い換えただけの問題は、聴いていなくても常識で当たる。当たっても何も残らない。
そうではなく、**似た4つの場面を並べて、どれが該当するかを選ばせる**。

| 弱い問い方 | 効く問い方 |
|---|---|
| AIエージェントとは何ですか | 次の4つの働かせ方のうち、**エージェントに任せていると言えるのはどれか** |
| 頼み方の4点セットは何ですか | この依頼文には4点セットのうち1つが欠けています。**どれか** |
| 最初に着手すべき業務の条件は | 4つの実務を並べて、**最初に手をつけるのはどれか** |

誤答は**もっともらしいもの**にする。当日ひっくり返した通説（「使い込めば覚えてくれる」
「同じスレッドを使えば前提が残る」など）をそのまま置くと、外した人ほど解説が刺さる。
正解の位置は固定しない（`data-a` を散らす）。

点数はブラウザの中（localStorage）だけに残る。どこにも送らない。
2回目以降は「これまでの最高」が出るので、後日もう一度やらせる導線になる。

```bash
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_quiz.py list     # どの資料に何問入っているか
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_quiz.py refresh  # 見た目を直したとき、当て直す
```

## 会場に見せるQR画面（全資料）

壇上のパソコンで **`qr` と打つと、全画面にQRコードと個別パスワードが出る**。
聴いている人はカメラを向けるだけで、その資料を開ける。

**表・裏を問わず、個別パスワードを持つ資料すべてに入る。**
講演で1本だけ見せたいときも、「この資料はここです」とそのまま渡せる。
対象は台帳が正で、`apply_qr.py` が台帳に個別パスワードのあるものを拾う。
道具のページ（台帳・裏資料置き場・資料マトリクス）はマスターだけで開き、
個別パスワードを持たないので自然に外れる。

**個別パスワードが載るのは、ここだけ。** 裏資料置き場には書かない。
置き場は投影することがあるので、書いておくと全資料の鍵が一度に映ってしまう。

URLを読み上げるのは無理があるし、短縮URLは外のサービスに依存する。
パスワードは口頭で言うと必ず聞き返される。**両方まとめて画面に出せば済む。**

```bash
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_qr.py          # 入れる（冪等）
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_qr.py list     # 何のURLが入るか
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_qr.py refresh  # 見た目を直したとき、当て直す
```

QRの升目は `qrgen.py` がビルド時に作り、SVGとして資料の中に焼く。
**実行時に何も取りに行かない。** 資料は暗号化されて配られるので、
外の部品を読み込む作りにすると、鍵の中から外へ通信が出てしまう。

`qrgen.py` は標準ライブラリだけで動く（バージョン1〜10・誤り訂正レベルM）。
直したときは必ず読み取りで確かめる。**升目を他の実装と突き合わせても一致しない**
（詰め物の付け方が実装ごとに違い、規格上はどちらも正しい）。

```bash
pip install opencv-python-headless numpy      # 確認のときだけ要る
python3 .claude/skills/ozaken-shiryo/scripts/qrgen.py --verify
```

QR画面に出る題とパスワードは**パスワード台帳から取る**。
資料を作り直して題が変わったら、台帳も直してから `refresh` する。
台帳が古いと、会場のスクリーンに古い題が出る。

## SNSに貼られたときの見え方

資料は暗号化されているので、**SNSのクローラーが読むのは鍵のかかった外側だけ**。
何もしないと、どの資料を貼っても「🔒 資料アーカイブ ─ おざけん」しか出ない。

`apply_ogp.py` が、暗号の内側から題と概要を取り出して、外側の `<head>` に
OGP と `description` を入れる。**中身は触らないので、配布済みのパスワードは無事。**

```bash
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_ogp.py plan   # 何が入るか見る
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_ogp.py apply  # 入れる（冪等）
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/apply_ogp.py cards  # 共有カードの画像を刷り直す
```

新規公開は `publish.py` が `apply` まで自動で通す。**画像だけは `cards` を手で回す**
（Playwrightと書体の取得が要るため）。題を書き換えたときも `apply` と `cards` の両方。

概要は、内側の `<meta name="description">`。無ければ表紙のひとことで代える。
**新しい資料には description を書く。** 表紙のひとことは詩的なことが多く、
一覧で並べたときに何の資料か分からないことがある。

## 資料どうしをつなぐ

同じ概念が何本もの資料に出てくる。放っておくと、資料ごとに少しずつ違う説明が
書かれて、どれが正しいのか分からなくなる。

そこで**概念ごとに「正典となる資料」を1本決めて**（`.claude/skills/ozaken-shiryo/scripts/crossref_data.py`）、
他の資料からはそこへリンクを張る。資料が点ではなくグラフとしてつながり、
説明を直すときも「どこを直せば全体の整合が取れるか」が分かる。

**新しい資料を作ったら、`crossref_data.py` に足す。**
その資料が正典になる概念があるなら、そこに登録する。

```python
'Copilot Credits': ('03_tools/copilot-credits.html',
    ['Copilot Credit', 'クレジット'], '使った分だけ課金される仕組み'),
```

リンクは**話が重なるセクションの末尾に、小さなチップとして置く**。
資料の最後にまとめて並べても、そこまで送られることは少ないので、
「この話は、あの資料でも扱っている」をその話をしている場所に出す。

```bash
cd .claude/skills/ozaken-shiryo/scripts
OZAKEN_PW=マスター python3 crossref.py map      # どの資料がどの概念に触れているか
OZAKEN_PW=マスター python3 crossref.py check    # 説明や数字が食い違っていそうな箇所
OZAKEN_PW=マスター python3 crossref.py preview  # どのセクションに何が並ぶかを見る
OZAKEN_PW=マスター python3 crossref.py apply    # チップを挿入
OZAKEN_PW=マスター python3 crossref.py matrix   # 資料×概念の一覧ページを作り直す
```

**当てる前に必ず `preview` で見る。** 拾い方は2通りあって、
`crossref_data.py` に登録した概念は低い敷居で、
本文の語の重なりだけで見つけたものは高い敷居で通している。
後者はどうしても外れが混じるので、ひどい組み合わせが出るなら敷居を上げる。

`apply` は一度入れた資料には二度入れない。規則を変えて張り直すときは
`strip` してから `apply` する。

**資料マトリクス**（`mx` で開く）は、資料 × 概念の格子。
どこにもつながっていない資料と、正典の外で厚く扱われていない概念が
そのまま抜けとして出るので、資料を足したあとに一度見ておく。
