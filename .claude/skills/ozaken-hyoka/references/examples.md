# 弱い書き方と、直したあと

抽象的に「弱い」と言われても直せない。
**どう弱くて、どう変えると強くなるか**を、対比で持っておく。

## 見出し

| 弱い | 強い | なぜ |
|---|---|---|
| Copilot Credits の概要 | 1クレジット＝$0.01。買い方は2つしかない | 見出しだけで主張が伝わる |
| AI人材育成の重要性 | 使う人を育てても、設計する人がいないと止まる | 反対の立場がありうる |
| 生成AIの活用事例 | 成果が出た会社は、例外なく「正本」を1つ決めていた | 発見がある |
| 今後の展望 | 3年後、この仕事は「頼む仕事」に変わる | 言い切っている |

体言止めは、たいてい主張から逃げている。**述語で言い切る。**

## 主張

**弱い：** 「生成AIの活用が進んでおり、多くの企業が導入を検討しています。」
→ 全員が知っている。この1行に価値は無い。

**強い：** 「導入した会社の多くは、いま2周目で詰まっている。
1周目は『使ってみる』で成立したが、2周目は『任せる』なので、
渡すデータが揃っていないと動かない。」
→ 聞いている人の現在地に名前を付けている。

---

**弱い：** 「AIエージェントは自律的にタスクを実行します。」
→ 定義の再掲。

**強い：** 「エージェントは、脳と記憶と手足でできている。
つまずくのはたいてい手足ではなく、記憶のほうだ。」
→ 分解の仕方が、そのまま診断の道具になっている。

## 数字の置き方

**弱い：** 「クレジットの単価は $0.01 です。」

**強い：** 「1クレジット＝$0.01。つまり、1タスク30クレジットなら30円。
月100回まわしても3,000円で、**人件費と比べる土俵にすら乗らない**。
高いか安いかではなく、はじめて金額として見えるようになった、という話。」

数字だけ置くのは資料集。**その数字が何を意味するかまで書いて、資料になる。**

## 分類

**弱い：** 大企業 / 中小企業 / 製造業 / DX推進部門
→ 規模・業種・部門の3つの軸が混ざっている。聞いた人は分類を信用しなくなる。

**強い：** 導入のしやすさ × 効果の大きさ の2軸で置く
→ 軸が明示されていて、自分の会社をどこに置くか考えられる。

---

**弱い：** 経営層 / 現場 / 情シス / 田中さん
→ 粒度が揃っていない。

**強い：** 決める人 / 使う人 / 支える人
→ 役割で揃っている。どの会社にも当てはめられる。

## 締め

**弱い：** 「以上、Copilot Credits の仕組みと、見積りの立て方を解説しました。
まずは自社の利用状況を把握することから始めましょう。」
→ 要約＋一般的な行動喚起。ここまで聴いた人には、何も足していない。

**強い：** 「この変化の本質は、値上げでも値下げでもない。
AIの使い方が、はじめて金額として見えるようになったということだ。
見えるようになったものは、必ず管理の対象になる。」
→ 一段上の視点に引き上げている。持ち帰れるのはこちら。

**締めで事実を要約しない。** 要約は聴衆が自分でやる。
資料がやるべきなのは、**その事実をどう捉えるか**を渡すこと。

## デザインの単調さ

**単調：** 9面すべてが「3つのカード＋箱を並べた図」
→ 内容は違うのに、送っても景色が変わらない。
聴衆は「いま何枚目か」を見失い、集中が切れる。

**直し方：** 数字を見せる面は `fig_stats`、比較は `fig_versus`、
判断は `fig_check`、構造は `fig_tree` に散らす。
**同じかたちを3面以上続けない。**

---

**単調：** 赤が全面に散っている
→ どれも目立たなくなる。

**直し方：** 1面に1箇所。ただ目立たせたいだけの箇所はAMBERに落とす。
赤は「危険」か「ここが要点」のときだけ。
