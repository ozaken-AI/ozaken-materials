# 週次AIニュース → 反映提案

## この仕組みの絶対ルール

1. **既存資料（各HTML）は、おざけんの承認なしに1文字も書き換えない。**
   提案は必ず「提案ファイル ＋ PR本文」の形で出し、承認を得てから初めて適用する。
2. **`main` に直接pushしない。** 必ず作業ブランチ → PR。マージはおざけんが行う。
3. **`index.html` は週次ジョブでは触らない。** トレンド枠の更新は月次ジョブ（`ai-news-monthly`）の担当。
4. 触ってよい／いけないファイルは `references/material-map.md` の定義に従う。

---

## Phase 1 ── 対象期間を決める

土曜朝に走る前提。対象は **直前の日曜〜土曜（当日を含む7日間）**。
ISO週番号で `YYYY-Www` を作る（例: 2026-W31）。日付は必ず `date` コマンドで取る。憶測で書かない。

```bash
date +%Y-%m-%d
date +%G-W%V          # ISO週番号
date -d 'last sunday' +%Y-%m-%d
```

同じ週番号のダイジェストが `10_ニュース/weekly/` に既にあれば、**新規に作らず既存を更新する**（二重投稿の防止）。

## Phase 2 ── ニュースを集める

`references/sources.md` を読み、そこに書いた検索の型・採否基準・件数上限に従う。
`WebSearch` を最低6本、日本語と英語を混ぜて投げること。

## Phase 3 ── 週次ダイジェストを書く

`10_ニュース/weekly/YYYY-Www.md` を新規作成する。ひな形は `10_ニュース/weekly/2026-W31.md` を実例として見ること。

構成:

```markdown
# 週次AIニュース YYYY-Www（M月D日〜M月D日）

> 今週の総括を2〜3文。何が起きた週だったかを一言で言い切る。

## 生成AI
### YYYY-MM-DD ─ 見出し
- 出典: URL
- 何が変わるか: 1〜2文
- 関連資料: パス（無ければ「なし」）

## AIエージェント
（同じ形式）

## フィジカルAI
（同じ形式。該当なしの週は「今週は特筆なし。」と書く）
```

ダイジェストは新規ファイルの追加なので、既存資料を壊さない。**ここまでは承認不要。**

## 前提 ── 既存資料はパスワード暗号化されている

`index.html` と `10_ニュース/` 以外のHTMLは、本文がAES-GCMで暗号化されている（ロック画面＋暗号文だけがコミットされている）。
つまり **パスワードが無いと、中身を読むことも書き換えることもできない。**

パスワードは環境変数 `OZAKEN_ARCHIVE_PW` から渡す。付属ツールを使う:

```bash
S=.claude/skills/ai-news-weekly/scripts/archive_crypto.py
python3 $S selftest                                  # ツールの動作確認（パスワード不要）
python3 $S decrypt 対象.html -o /tmp/plain.html      # 本文を取り出す
python3 $S encrypt 対象.html /tmp/plain.html         # 編集した本文を詰め直す
```

コンテンツ鍵は使い回されるので、**再暗号化しても既存のパスワードはそのまま生きる**。

### パスワードが無いときの振る舞い

`OZAKEN_ARCHIVE_PW` が未設定なら、**そこで止まらず、提案までを出し切って終わる**。
その場合はPR本文とSlackに次を明記する:

> ⚠️ アーカイブのパスワード（`OZAKEN_ARCHIVE_PW`）が環境にないため、承認をもらっても本文の書き換えができません。
> 提案の適用は手元でお願いします。自動反映まで通したい場合は環境変数を設定してください。

パスワードをリポジトリ・PR本文・Slack・コミットメッセージに書かないこと。**絶対に。**
`cryptography` の読み込みに失敗したら `pip install cffi` を試す。

## Phase 4 ── 反映提案を作る（HTMLは書き換えない）

`references/material-map.md` を読み、今週のニュースが効く既存資料を洗い出す。
パスワードがあるなら、対象資料を `decrypt` して**実際の本文を読んでから**提案を書く
（読まずに書いた提案は、たいてい既にある記述と重複する）。復号した一時ファイルは
`/tmp` 配下に置き、**リポジトリ内には絶対に置かない**。作業後に消す。
`10_ニュース/weekly/YYYY-Www-反映提案.md` に、提案を **番号つき** で書く。

各提案に必ず含めるもの:

- **提案番号**（`#1`, `#2` …）
- **対象ファイル** と、**その中のどの箇所か**（見出し名や現在の記述を引用して特定できるように）
- **現状の記述**（該当箇所の原文を引用）
- **変更案**（実際に入れる文面。「〜を追記」ではなく、入れる文そのものを書く）
- **根拠ニュース**（Phase 3 の項目へのリンク）
- **やらない場合のリスク**（1文。「放置すると価格表が古いままになる」など）

提案は **多くて5件**。多いほど確認が面倒になり、結果として全部放置される。
迷ったら削る。「今週は反映すべき点なし」で終わる週があってよい。

> ⚠️ この段階で既存HTMLを編集してはいけない。差分は提案文の中に文字として書くだけ。

## Phase 5 ── ブランチとPR

```bash
git checkout main && git pull origin main
git checkout -b claude/news-YYYY-Www
git add "10_ニュース/weekly/"
git commit -m "週次AIニュース YYYY-Www とその反映提案"
git push -u origin claude/news-YYYY-Www
```

`mcp__github__create_pull_request` で PR を作る（base: `main`）。

- タイトル: `週次AIニュース YYYY-Www ─ 反映提案 N件`
- 本文: 今週の総括 → **提案一覧をチェックボックスで列挙**（番号・対象ファイル・一行要約）→ 承認方法の案内

本文末尾に必ずこの案内を入れる:

```markdown
---
### 反映のしかた
このPRの時点では**既存資料は一切変更していません**。反映してよい提案の番号をコメントしてください。

- `#1 #3 OK` … その番号だけ反映します
- `全部OK` … 全提案を反映します
- `#2 却下` … 却下として記録し、反映しません
- `#1 ただし価格表だけ` … 条件つきも書いてください。そのとおりに反映します
- `なし` … 何も反映せず、ダイジェストだけ残します

反映後、このブランチに追加コミットします。マージはおざけんが行ってください。
```

PR本文末尾には Claude Code のアトリビューションフッターを付ける。

作成後、`mcp__Claude_Code_Remote__subscribe_pr_activity` でこのPRを購読する。

## Phase 6 ── Slackで通知

おざけん本人へDMを送る（`mcp__Slack__slack_send_message`、`channel_id: U078WMGJFRR`）。

```
📰 週次AIニュース YYYY-Www をまとめました

今週の総括を1〜2文。

**反映提案 N件**
1. 対象ファイル ─ 一行要約
2. …

PRで確認して、反映してよい番号をコメントしてください（例: `#1 #3 OK` / `全部OK` / `なし`）
→ PRのURL
```

提案が0件の週も、**必ず通知する**（「今週は反映提案なし。ダイジェストだけ置きました」）。
沈黙すると、仕組みが動いているのか判断できなくなる。

### PR作成やSlack送信の手段が無いとき

定期実行のセッションには、`mcp__github__*` や `mcp__Slack__*` が渡っていないことがある。
**その場合でも、途中で投げ出さない。** 次の順で代替する。

1. **ブランチのpushは必ず完了させる。** これはgitコマンドだけでできる。成果が消えない
2. PRが作れないときは、pushの出力に出る PR作成URL
   （`https://github.com/ozaken-AI/ozaken-materials/pull/new/<ブランチ名>`）を控える
3. Slackが使えないときは、**セッションの最終出力に通知内容をそのまま書く**。
   このRoutineはプッシュ通知が有効なので、完了時におざけんの端末に要約が届く
4. 最終出力の冒頭に、次を必ず書く

   > ⚠️ このセッションにSlack／GitHubのツールが渡っていませんでした。
   > ブランチは push 済みです: `<ブランチ名>`
   > PR作成: `<PR作成URL>`
   > 反映提案は `10_ニュース/weekly/YYYY-Www-反映提案.md` にあります。

恒久的に直したいときは、claude.ai の Routine 設定画面から Slack / GitHub のコネクタを
このRoutineに紐づけ直す（コマンドラインからは付与できない）。

## Phase 7 ── 承認を受けて反映する

PRのコメントが `<github-webhook-activity>` として届いたら:

1. **承認された番号だけ** を対象にする。番号が曖昧なコメント（「いい感じ」など）は反映せず、PRに返信して番号を聞き直す。
2. 対象HTMLを編集する。編集は提案に書いた変更案どおりに行う。**ついでの修正を混ぜない。**

   ```bash
   S=.claude/skills/ai-news-weekly/scripts/archive_crypto.py
   python3 $S decrypt "対象.html" -o /tmp/plain.html
   # /tmp/plain.html を Edit で書き換える（提案どおりに、そこだけ）
   python3 $S encrypt "対象.html" /tmp/plain.html
   python3 $S decrypt "対象.html" -o /tmp/verify.html && diff /tmp/plain.html /tmp/verify.html && echo "詰め直しOK"
   rm -f /tmp/plain.html /tmp/verify.html
   ```

   再暗号化すると暗号文全体が変わるため、**git diff では変更内容が読めない**。
   だからPRの本文に「復号後の差分」を必ず貼ること。これを省くとレビューが不可能になる。

   ```bash
   diff -u <(python3 $S decrypt "対象.html.orig") <(python3 $S decrypt "対象.html") | head -60
   ```

3. 提案ファイルの各提案に結果を追記する（`✅ 承認・反映済み` / `❌ 却下` / `⏸ 保留`）。日付も残す。
4. コミットしてPRブランチにpush。復号した一時ファイルが混ざっていないか `git status` で必ず確認する。

```bash
git add -A && git commit -m "承認された反映提案を各資料に適用（#1 #3）"
git push origin claude/news-YYYY-Www
```

5. PRに1回だけ返信する（何を反映し、何を却下したか）。**1件ずつ返信しない。**
6. マージはおざけんに任せる。こちらでマージしない。

却下された提案も、削除せず記録として残す。同じ提案を翌週また出さないための履歴になる。

## Phase 8 ── PRが閉じるまで見届ける

マージ or クローズされるまで購読を続ける。CIは無い（静的サイト）が、コンフリクトの通知が来たら `main` を取り込んで解消する。
マージされたら `unsubscribe_pr_activity` する。

## よくある事故と、その回避

| 事故 | 回避 |
|---|---|
| 承認前に本文を書き換えてしまう | Phase 4 では文字列として提案を書くだけ。Editツールを既存HTMLに向けない |
| 提案が毎週10件を超えて放置される | 上限5件。迷ったら削る |
| 同じニュースを翌週も提案する | 過去4週の `*-反映提案.md` を先に読み、却下済みを除外する |
| 価格の記述を推測で書き換える | 価格は必ず公式の料金ページを `WebFetch` で確認してから提案する |
| ダイジェストの日付がずれる | `date` コマンドの出力を使う。記憶で書かない |
| 復号した平文をコミットしてしまう | 一時ファイルは `/tmp` 配下だけ。pushの前に `git status` を見る |
| パスワードがログやPRに漏れる | 環境変数から読むだけ。コマンドラインに `--password` で書かない |
| 再暗号化でPRが真っ黒な差分になる | PR本文に復号後のdiffを貼る（Phase 7-2）|
