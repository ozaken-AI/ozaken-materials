# 週次トレンドの作り方（システム設計）

トップページに「今週のトレンド」を置き、パスワードで守る。そのために
**あの深さの情報が毎週集まる仕組み**を先に作る。この文書はその設計。

---

## 1. 「深さ」の正体を、先に分解する

参考にしたメルマガ（週刊 Life is beautiful）の1本を分解すると、深さは
文章力ではなく**材料の作り方**から来ている。成分は6つ。

| 成分 | 具体 | 自動化 |
|---|---|---|
| ① 一次情報に降りている | 契約条件を箇条書きにできる（〜2028年／750MW／$20B超／ワラント最大10%） | できる |
| ② 仕組みで説明している | 「なぜ速いか＝ウェハースケールで重みをオンチップに載せ、HBM往復が無い」 | できる |
| ③ 定点で見ている | 「上場前に見送った」「Groqの件で勝ち目が薄いと思った」→ 今回の更新 | **記憶の設計が要る** |
| ④ 数字が一枚に並ぶ | Vals Index の表、$/1Mトークン、$/MWh | できる |
| ⑤ 賭けが書いてある | 「10年で搭載義務化」「少し買った」 | **できない（人）** |
| ⑥ 読者の質問が入る | 質問コーナー | 半分できる（ask.html が既にある） |

ここから仕様が決まる。収集システムが出すべき最小単位は
**「記事の要約」ではなく、次の6項目が埋まった1枚のカード**である。

```
{ "何が起きたか": "事実。日付つき",
  "出典":     ["一次情報のURL", ...],       # 二次情報しか無いなら、その旨を明記
  "数値":     [{"値","単位","期間","出典","確認日"}],
  "仕組み":   "なぜそうなるのか。技術・契約・経済の構造",
  "差分":     "前週までの定点ファイルとの違い",
  "外れる条件":"この見立てが崩れるとしたら、何が起きたとき" }
```

「仕組み」と「外れる条件」を必須にするのが肝。ここが埋まらない話題は、
どれだけ話題になっていても**今週は載せない**。これだけで、
ニュースまとめと解説の差がつく。

## 2. 層構造

```
L0 定点表        watchlist.yml       … 何を見続けるか
L1 収集（毎日）   collect.py          … 一次情報のフィードを舐める
L2 選別（毎日）   軽いモデル           … 300件 → 30件
L3 深掘り（週1）  1件1エージェント      … 原典必達。上のスキーマを埋める
L4 検証（週1）    別エージェント        … 数値を原典に突き合わせる。落ちたら降格
L5 合成（週1）    束ねる・図にする      … おざけんのコメント欄は空けて出す
L6 公開（週1）    publish.py          … 暗号化・台帳登録・index 掲載
```

L0 と L3 の間に L1/L2 を挟むのは、コストのため。毎日の収集と選別は安く回し、
高いモデルは**週に8件の深掘りだけ**に使う。

---

## 3. 収集元（L1）

**方針: 一次情報を厚く、二次情報は見出しだけ。** 有料記事の本文は取りに行かない。

| 層 | 具体 | 取り方 |
|---|---|---|
| 企業の発表 | OpenAI / Anthropic / Google・DeepMind / Meta AI / NVIDIA / AMD / Microsoft / AWS / Cerebras / Groq / xAI / Mistral | 各社ニュースルームの RSS |
| 開示 | SEC EDGAR 全文検索API（8-K, 10-Q, S-1）、TDnet 適時開示 | 公開API |
| 政策 | 経産省・総務省・個人情報保護委員会・デジタル庁・内閣府、EU AI Act、NIST | 新着RSS＋審議会PDF |
| 研究 | arXiv API（cs.AI / cs.CL / cs.LG）、Hugging Face papers | 公開API |
| 計測 | Artificial Analysis / LMArena / Vals AI / Epoch AI | ページ差分監視 |
| 価格・仕様 | 各社 pricing ページ | **差分監視**（前回HTMLのハッシュ＋抽出値） |
| 現場の温度 | Hacker News（点数閾値＋語）、GitHub Releases / Trending | 公開API |
| 日本の動き | ITmedia・日経xTECH（見出し）、PR TIMES のAIカテゴリ | RSS |

**価格ページの差分監視を必ず入れる。** モデル料金の改定はプレスリリースにならず、
ページが黙って書き換わる。前週の値を持っていないと気づけない。ここは
既存資料（`03_tools/claude-guide.html` など）の数字の鮮度にも直結する。

### 取れないもの、と、その埋め方

- **X** … 無料APIが無く、スクレイピングは規約違反。自動収集しない
- **有料メディア**（The Information / Bloomberg など）… 本文を取らない

この2つが実は効く。参考メルマガの Cerebras の回も、
きっかけは「Xで見かけた投稿」だった。だから**人からの投げ込み口を、
システムの正式な入口として作る**。

> Slack に専用チャンネルを作り、おざけんが URL や一行メモを投げると、
> 翌朝の収集がそれを**最優先の候補**として拾う。
> （この環境には Slack MCP が繋がっているので、追加の実装はほぼ要らない）

投げ込みは L2 の選別を通さず、無条件で L3 の深掘りに進める。
「気になった」という人間の信号は、どんなスコアより強い。

## 4. 定点（L0）── 週をまたぐ記憶

**ここが、毎週やって深くなるか、毎週ゼロから始まるかの分かれ目。**
これが無いと、何週やっても「今週のニュース一覧」にしかならない。

`weekly/threads/<slug>.json` を話題ごとに持つ。

```json
{ "slug": "cerebras",
  "watching": ["Cerebras", "ウェハースケール", "高速推論", "G42"],
  "facts":    [{"date":"2026-01-14","text":"OpenAIと750MW／$20B超の契約","src":"..."}],
  "open":     ["G42はOpenAI向けDCの資金に入るか", "NVIDIA+Groqの製品はいつ出るか"],
  "stance":   "取った契約を期限内に建て切れるかにリスクが移った",
  "falsify":  "2026Q4までに着工が発表されなければ、この見立ては外れ",
  "written":  ["weekly/2026-08-18.html"] }
```

L3 の深掘りエージェントは、**必ずこのファイルを読んでから書き、書き終えたら
`facts` / `open` / `stance` を更新して戻す**。翌週は差分から書き始められる。

「未解決の問い（`open`）」を持つのが効く。翌週以降、そこに答えが出た瞬間に
**それは自動的にトップ記事になる**。追う理由が先にあるから、深くなる。

## 5. 既存アーカイブとの接続

このリポジトリには既に68本の資料があり、`find.py` で全文検索できる（暗号化済みだが復号して探せる）。

- **数字が食い違ったら、古い資料のほうも直す。** 週次が新しい数字の入口になる
- **3週続いた話題は、解説資料に昇格させる。** 週次＝流れ、`0*_*`＝正典。
  昇格したら `crossref_data.py` に登録し、以後の週次からリンクを張る

これで週次が「消えていくコンテンツ」ではなく、**アーカイブを更新し続けるエンジン**になる。

## 6. 週の運転

| 曜日 | やること | 誰が |
|---|---|---|
| 毎朝 | L1 収集 → L2 選別 → 候補を積む（15分程度） | 自動 |
| 随時 | Slack に投げ込む | おざけん |
| 金 | L3 深掘り8件 → L4 検証 → コメント欄が空いた下書きが出る | 自動 |
| 土 | 下書きを読み、**取り上げる話題を絞り、コメントを書く** | おざけん |
| 日 | L5 合成 → 図版 → L6 公開・index 更新 | 自動＋確認 |

役割分担は、参考メルマガの著者と同じ形にする。

- **どの話題を載せるか … 人**
- 調査・要約・裏取り・誤字 … AI
- **意味づけのコメント … 人（ここだけは手書き）**
- 分かりやすさの最終確認 … 人

自動化するのは材料集めまで。⑤の「賭け」を書けるのは本人だけで、
そこがこの週次の価値になる。

## 7. 鍵と公開範囲（決定済み）

- **鍵は「マスター＋週次購読キー＋その週の1語」の3本。**
  資料アーカイブの共通キーは付けない。週次を渡した相手に資料68本は開かず、
  資料を渡した相手に週次も開かない
- 購読キーは `lockbox.add_password` で後から足せるので、**四半期ごとにローテできる**
  （`add` → `remove` の順。本文の再暗号化は起きず、マスターと個別の鍵は生きる）
- その週の1語は既存ルールどおり **小文字英字4〜10文字・一意**。その週の主題の1語にする
- **トップページには、最新4週の題とリード3行までを平文で出す。** 本文は鍵。
  既存の「アーカイブは限定公開です」の枠と同じ体裁を使う

## 8. 既存パイプラインへの改修点

新規に書くものより、**既に動いているものへの追記のほうが多い**。

| 対象 | 何をするか |
|---|---|
| `oz_root.BACKSTAGE_DIRS` | `'weekly'` を足す。走査する道具（`check_pw` / `registry` / `reapply` / `apply_qr`）が全部追随する |
| `check_pw.py` | 週次は「共通キーが付いていないこと」を検査する側に回す（現在の `TOOLS` と同じ扱い） |
| `publish.py` | `add_to_index()` は `0*_*` 分類前提なので、`add_to_weekly()` を新設（最新4週だけ残して古い号は一覧ページへ送る） |
| `build_page.check()` | 週次は資料と形が違う（セクション偶数・図版必須などが合わない）ので、週次用テンプレを別に持つ |
| `registry.py` | 週次も台帳に載せる。号数と主題の1語を記録 |
| `apply_qr.py` | 週次にも QR 画面を入れる（登壇の最後に「今週のトレンド」を出せる） |
| `find.py` / `crossref.py` | 深掘りの前に必ず通す。既存資料と数字・主張が割れていないか |

## 9. いま塞がっている穴（要対応）

**このリモート環境は、外部への通信がほぼ全部ブロックされている。** 実測結果:

| | 結果 |
|---|---|
| `curl https://openai.com/news/rss.xml` | 403（CONNECT をゲートウェイが拒否） |
| `WebFetch` で cerebras.ai / sec.gov | `EGRESS_BLOCKED` |
| `WebSearch` | **通る**（検索結果とスニペットは取れる） |

つまり**いまのままでは、検索はできても原典に降りられない**。
①一次情報が成立しないので、この設計の核が動かない。

環境設定で以下のドメインを許可すれば解決する（Claude Code on the web の環境設定）。
まずはこの一覧から。

```

blogs.microsoft.com news.microsoft.com aws.amazon.com nvidianews.nvidia.com
blogs.nvidia.com amd.com cerebras.ai groq.com x.ai mistral.ai sakana.ai preferred.jp
# 開示・IR
sec.gov efts.sec.gov ir.tesla.com release.tdnet.info jpx.co.jp
# 政策
meti.go.jp soumu.go.jp ppc.go.jp digital.go.jp cao.go.jp cas.go.jp
digital-strategy.ec.europa.eu nist.gov
# 研究

# 開発・現場
```

許可が下りるまでは、WebSearch のスニペット止まりになる。
その状態で書くと**②仕組みと④数字が埋まらない**ので、
穴が空いたまま publish せず、`open` に積んで翌週に回す運用にする。

### 号を1本作る手順

```bash
# 1) 前の号の src をコピーして本文を組む（数字は threads/*.json から引く）
cp weekly/src/2026-08-18.py weekly/src/2026-08-25.py

# 2) フラグメントを書き出して、スタイル検査だけ先に通す
python3 weekly/src/2026-08-25.py /tmp/body.html
python3 .claude/skills/ozaken-shiryo/scripts/build_page.py /tmp/body.html /tmp/page.html

# 3) 公開（暗号化 → 台帳 → トップページ掲載まで一括）
OZAKEN_PW=マスター python3 .claude/skills/ozaken-shiryo/scripts/weekly_publish.py \
    /tmp/body.html 2026-08-25 --pw <その週の1語> \
    --title "…" --lead "トップに平文で出る3行"

# 4) 面ごとに絵で見る（1画面に収まらない面が出ていないか）
OZAKEN_PW=マスター node .claude/skills/ozaken-shiryo/scripts/shot_secs.mjs \
    weekly/2026-08-25.html /tmp/secs
```

本文だけ直すときは `--update` を付ける。**鍵は作り直されないので、配布済みの購読キーは生きる。**

### 組むときの制約（`build_page.check` が見ている）

- **`<table>` は使えない。** 数字は `domain_fig` の `fig_sheet` / `fig_stats` / `fig_bars` / `fig_donut` で図にする
- **本文セクションは奇数本**、明るい面と暗い面が交互、**末尾はネイビー**
- カードの見出しに番号チップ（`.mth`）を入れない。`card-tag` が既に番号を振っていて二重になる
- `fig_stats` の見出しは**14文字以内**。超えると3行に折り返して注記と重なる

### 鍵

| 鍵 | 誰に | 備考 |
|---|---|---|
| マスター | おざけん本人 | すべてを開く |
| 週次購読キー `_meta.weekly` | 週次の購読者 | 全号に共通。四半期ごとに付け替える |
| その週の1語 | 会場・当日の配布 | 小文字英字4〜10文字。台帳が重複を弾く |

**資料アーカイブの共通パスワードは付けない。** 資料をまとめて渡した相手に
週次まで渡ってしまうため。逆に、週次を渡した相手に資料92本は開かない。
（`weekly/2026-08-18.html` で実際に確認済み）
