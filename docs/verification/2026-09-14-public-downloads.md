# トップ配布の3資料を初心者向けに改訂

対象は本人が指定した5レベル・業務変革大全・51施策の公開PDFとトップの対応する配布案内。元の17配布PDFの監査から、この3つに絞って内容を改善した。その他の配布物・講演HTML・テンプレート・トップの隠し操作は変更していない。

## 変更内容

| 資料 | 旧 → 新 | 初心者が自力で進めるために補ったもの |
|---|---|---|
| 5レベル | 17 → 29ページ | ゴールと読む順番・必要なアカウント・Gemの作成・固定指示全文・架空の入力・期待結果・3種のテスト・Workspace Studioの起動と変数と自分への通知・トラブル時の確認・A4縦の設計シート |
| 業務変革大全 | 14 → 28ページ | 週次報告のSIPOC・記入順・エージェント設計との対応・3基準の工程判定・標準化・HTA/CTA/ECRS/RACIの記入例・台帳・効果計算・4枚のA4縦シート |
| 51施策 | 1 → 16ページ | 先頭のA4横一覧を維持・困りごとから選ぶ案内・1施策の実行例・全51項目の意味/行動/担当/成果物・用語集・A4縦の実行シート |

5レベルの分類・3トリガー・コンテキストとハーネス・AI型化・戦略/設計/運用の役割は残して再構成した。製品比較を初心者の開始条件にせず、1つのGoogle環境で具体的な操作例を示した。Agent 365をレベル5の具体製品とする旧表現は、公式の管理・統制基盤という位置づけに修正。出典や関連資料は読めるURLとリンク、配布元QRで案内する。

業務変革の効果計算は単位を明確にした。仮の90分から作成20分・確認15分・運用5分を引くと正味50分、年48回で40時間、時間単価3,000円なら120,000円相当。時間価値と支出削減を区別し、初期構築・追加費用も比較する。根拠のない差し戻し率による一律の確認省略は案内しない。

51施策の名称と番号は旧PDFから文字を抽出し、新一覧と全51件照合して一致した（空白・全半角等の組版差は正規化）。詳細表も同じ51件の順序と番号で照合済み。旧版のフェーズ別件数は対応表がなく、関連する基盤フェーズHTMLにも番号/名称の食い違いがあるため、新しいPDFでは割当を推測しなかった。範囲外の関連HTMLは変更していない。

## デザインと印刷

- 3書体・紺/紙色・広い余白・固定の章見出しを統一 表/手順/流れ/カード/記入シートを用途ごとに使い分けた
- カバーは抽象的な軌道と光点で統一 句読点を入れず 図解可能な内容に依存させない
- PDFは全情報を静止表示 クリック切替や開閉式の内容はない
- 5レベルと業務変革の解説は16:9 記入シートはA4縦 51施策は既存に合わせA4横の一覧と解説＋A4縦の実行シート
- 長い表は縮小せず分割 システム実装の8項目は2ページに分けた
- 共通組版で未収録グリフ・文字枠超過・フッター侵入を拒否 Shipporiにない全角区切り記号は見出しから除いて再検証した

## 検証

- 3PDF、計73ページをPopplerで長辺1440pxのPNGに描画し 全ページを4枚ずつのコンタクトシートで確認
- コピー用指示・操作手順・期待結果・3つのQRページ・記入欄を拡大確認
- `beginner_guides/check.py`：73ページの本文と見出しが生成元どおり存在 ページ外の文字なし リンク矩形も用紙内 参照ページ番号の範囲も確認
- 全51項目の名称・通し番号・詳細表・先頭一覧を照合
- 架空の案件の3件/100万円と 効果計算を検算
- QR3件をPNGからZXingで復号し `https://content.ozaken.ai/` と一致
- トップの変更は対象3カードの画像・alt・説明・ページ数のみ ダウンロード先と `download data-gate` を保持 対象外部分の一致を検査
- 日本語本文は埋め込みフォントで選択・検索可能 本文JSONとフォントロックから生成できる
- `git diff --check` と `scripts/version-site-assets.py --check` は合格
- 公開前の `check_design.py --staged` で122資料を確認 デザインの適用漏れ0件
- ReportLabのPDFをGitがテキストと誤認しないよう 対象3パスを `.gitattributes` でbinary指定

画像描画とPDFの検査は実行したが、Googleアカウント内でGem/フローを実際に作成した検証、初心者の実参加によるユーザーテスト、紙への実印刷は未実施。Computer Use権限がない環境であり、ブラウザの別経路による操作はしていない。操作例はGoogleの一次資料に照合し、アカウントで使用できない場合の代替手順を付けた。PDFの実装品質とサービス内での動作確認は同一視しない。
